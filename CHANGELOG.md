# Changelog

## Unreleased

- **Self-optimization now shows what it changed and proves whether it landed.** Each finding carries its verification commands and results, the independent review verdict, a diff summary and the commit; every session writes a human-readable report (`~/.qiansi/selfopt/<repo>/sessions/<id>.md`) covering stage status, per-finding evidence and outcome counts; the panel gains a history list with a 报告 viewer, a 查看证据 expansion, and a 核验落地 (git) button that checks each recorded commit is still an ancestor of HEAD. A failed run no longer masquerades as success — running stages are marked failed with the cause and unattempted findings get 「未执行：原因」, with a retry button that reuses the same mode/level/budget. All selfopt queries take `rootDir`, and the panel scopes them to the repo being optimized instead of always defaulting to Qiansi itself. Verified on an isolated repo with a real off-by-one bug: the run produced one finding, fixed `src/math.js`, passed `typecheck` and `npm test`, was approved by an independent reviewer, committed `d8a3e8b5`, wrote a report, and reported 1/1 landings — 17/17 API checks and 11/11 UI checks.

- **Duplicate canvases: the retry storm is capped, deduplicated, and no longer triggered by questions.** The real-time watcher treated every user message as a task — including the question 「qiansi的git仓库在哪」, which produced 16 identical canvases in one evening (one every ~2.6 minutes). Three causes were fixed: (1) questions without an action verb (`？/为什么/哪/如何…` and no 改/做/写/运行/修复/优化/部署…) are logged and skipped, while 「为什么失败，请修复」 still runs; (2) a failed handoff gives up after 3 attempts and says so in the watcher status instead of retrying forever; (3) `/api/handoff` reuses the same canvas for retries of the same request — the dedupe map is persisted to `~/.qiansi/handoff-attempts.json`, the key reaches it from the takeover watcher, the handoff modal and the MCP tool, and a retry skips re-arranging so nodes are not multiplied. The tab bar gains a 同名画布清理 button: it groups active tabs by name, keeps the newest, archives the rest into 历史画布 (recoverable) and shows the duplicate count. Generating a workflow into an empty canvas now fills that canvas instead of creating yet another tab. Verified: 21/21 UI (badge count, confirm, tabs collapse to unique names, archived count, legend), 7/7 watcher checks (retry cap, no replay, question skipped, action verb still runs), 10 existing duplicates archived leaving 6 distinct canvases.
- **Live runs actually start again — and a real run now finishes with a real deliverable.** `run.start` required a `relay` key for every canvas run even though the judge never used it; relay is disabled, so every takeover canvas was arranged, returned 503 `live_mode_missing_credentials`, and never ran (18 handoff arrangements, 0 run starts on 2026-11-13). Admission now requires only the worker slots plus one judge candidate that actually has a key (explicit judgeModel → orchestrator model → deepseek-v4-pro), and the 503 carries a hint. The structural acceptance gate also stopped failing short correct answers: it rejects only near-empty placeholders, the full judge gets a 2048-token budget, and an unparseable verdict gets one "return only JSON" repair round. Verified live: a two-node canvas ran end to end through deepseek-flash, finished `done`, produced 「1+1=2。」 with an explanation, passed acceptance 0.95, and recorded 1,591 tokens — 9/9 checks.
- **Tool calls are closer to usable on Windows.** `run_command` now tells the model it is cmd.exe on this machine (dir instead of ls, `&` instead of `&&`, `2>nul` instead of `2>/dev/null`), and subprocess output is decoded as UTF-8 with a GBK fallback so Chinese error messages no longer arrive as mojibake. Audit evidence: 261 run_command calls with 115 failures (44%), largely bash syntax and garbled output.
- **Canvas chrome no longer overlaps itself.** The bottom-left legend is now a collapsible Chinese pill (fold state in localStorage) whose colours match the real edge colours instead of the old mismatched English `assign/handoff/review/context`; the operation hint that sat at the same corner was merged into it. The zoom controls no longer cover the minimap (controls moved above it, minimap shrunk to 168×112 and hidden on narrow screens), and the workspace instructions panel uses fixed positioning so the 36px tab row no longer clips it.

- **GLM Coding Plan keys were calling the wrong endpoint.** Every GLM model failed with `1113 余额不足或无可用资源包` even though the subscription was fine; the stored key is a Coding Plan key, which only works on `open.bigmodel.cn/api/coding/paas/v4` — the standard `/api/paas/v4` endpoint rejects it. The model catalog and UI preset now use the coding endpoint, `completeChat` retries once on the coding endpoint when a standard Zhipu call returns 1113 (so ordinary pay-as-you-go keys still work), and old model entries in localStorage are migrated on load. Verified: direct chat through both base URLs returns text, a real team meeting finished 2/2 with the GLM member speaking, and the UI migration check passed 2/2.


- **Team members now have real capabilities, and the meeting shows everyone's feedback.** Each member carries a tool allowlist (read files, write files, shell, canvas queries, web search) that is enforced at runtime alongside the autonomy rung — a member without `write_file` never even sees the tool, and the executor refuses a forced call with 「请在会议里申请」. The team modal was rebuilt around this: compact member cards with avatars, model pickers fed by the server's key catalog (no more “not in catalog”), dashed partial capability chips, inline validation that disables saving, an unsaved-changes badge and close confirmation. The meeting is now a streaming endpoint (`POST /api/team/meeting`): each member gets a card with waiting/speaking/done/failed status, their message appears as soon as they finish, a per-speaker failure (e.g. an exhausted GLM balance) does not stop the rest, and a progress count shows `2/3 已发言`. Members who lack a tool can request it in one line (`TOOL_REQUEST: list_dir、run_command | 理由`); the server parses it into proposals and the user approves each with 批准并添加, which writes the capability immediately. New proposals auto-scroll into view. Verified: 37/37 deterministic (tool parsing incl. multiple tools per line, two-layer toolbox restriction, per-task `toolAllow`, meeting event sequence and single-member failure), 8/8 API (SSE events, structured proposal, approval persisted), 15/15 UI (capability toggles, validation, dirty/close confirm, per-member meeting cards, proposal approval).


- **Teams are now first-class: a roster, a playbook, and an autonomy rung per member.** Each canvas gets a team (one job per named member, a shared playbook, personal memory). Auto-arrange receives the roster and assigns each node to the member whose duty fits, the critic rejects off-duty assignments, and every task prompt carries that member's identity, rung and memory. The rung is enforced twice: investigate/draft tasks only receive read-only tools (`read_file`, `list_dir`, canvas queries, web search) and the executor refuses writes even if the model asks. The team modal edits the roster and playbook, warns about sprawl (>8 members) and overlapping duties, and can hold a staff meeting where members speak from their own duty and are told to disagree. Delegated and handoff canvases copy the team. Verified: 24/24 deterministic checks (validation, warnings, member prompts, plan injection, real orchestrator giving one task read-only tools and another all tools), 11/11 API (a real planner split 「核对 → 起草 → 校验」 across 小核/小稿/小核, and a two-member meeting produced a stated disagreement), 9/9 UI (editor, persistence after reload, assigning a node to a member).

- **Qiansi now checks its own work the way a user would.** After a run finishes `done` on a canvas that has an explicit working directory, the server starts the project (Vite/Next/`dev`/`start`/`preview`, or a built `index.html`), opens it in headless Edge/Chrome over CDP, and judges what a user can actually see: page responds, visible content exists, no uncaught/console errors, same-origin assets load, images render, there is something clickable, no horizontal overflow at 390 px, and the primary button does something. It saves desktop and mobile screenshots, writes 「用户视角验收」 onto the canvas, and exposes the evidence through `/api/user-view` (a modal shows the verdict, each check, and both screenshots). `payload.userView = false` turns it off. Verified: good fixture `pass` (9/9 checks, button click observed), deliberately broken fixture `fail` (content/console/interactive/overflow/visual all caught), real run → auto acceptance `pass` with two screenshots (8/8), failed-run → resume → done → auto acceptance `pass` (11/11), UI 16/16 plus a 4/4 compact-bar case. Electron and non-web projects report why they cannot be verified instead of pretending.
- **Failed runs now have a diagnosis and a deliberate re-run entry, not just an error line.** `GET /api/runs/:id/diagnosis` reports failed tasks, categorized reasons, whether the canvas working directory exists and is writable, whether each node's model still has a key (or was disabled by the user), remaining automatic-retry budget, and the available actions. The run strip gains a 诊断 panel with 「继续重跑」 (checkpoint resume), 「整轮重跑」 (re-plan from the current canvas), 「用户视角验收」, a one-click 启用 for a disabled provider, and an inline fix for a missing working directory. `POST /api/runs/:id/rerun` backs all of it and queues when another run is active. A stale `retryScheduled` flag from an older failure snapshot is now cleared once a resumed child run exists. Verified end to end: a failed run showed its two reasons, resume started a child run, that run finished `done`, and the old run correctly stopped advertising a scheduled retry.
- **Compaction summaries are no longer taken over as user requests.** Context-compaction text (`This session is being continued …`), `<system-reminder>` injections and pasted placeholders share the `user` role in transcripts; the watcher had launched a full canvas/run from one during this session. Ask discovery and the takeover watcher now share one injected-text filter. Harness 8/8.
- **A one-sentence deliverable is a valid deliverable.** The structural acceptance gate rejected any output under 20 characters without tool evidence, so a task explicitly asking for one sentence failed as 「产出为空或过短」 and took the run with it. The gate now only rejects near-empty output (<8 chars); whether a short answer satisfies the criteria is the judge's call.

- **Failed takeover runs now explain themselves and retry automatically.** When a run fails, the server builds a failure summary — failed task count, categorized reasons (budget / model key or quota / network timeout / acceptance), and the concrete per-task errors — stores it with the run, and writes a 「失败总结 · 第 X/3 次」 card onto the canvas. Takeover and queued runs set `autoResume`, so failures are retried from the last checkpoint with a hard cap of 2 automatic retries (3 attempts total); the summary says whether a retry is already scheduled. The run strip shows the same reasons plus a 重试 button that starts a manual resume. Also fixed the auto-resume request missing its workspace header, which made every automatic retry fail with `resume_workspace_mismatch` — that is why earlier takeovers never retried. Verified with a suspended Kimi key: three attempts all failed, attempt 1/3 reported `retry:true`, attempt 3/3 reported `retry:false`, the canvas card listed the 429 reason, and the UI passed 7/7 including clicking 重试 to start a fourth run.

- **A takeover that lands while another run is active now queues instead of stranding.** `run_in_progress` used to leave the freshly-built canvas idle forever (the "建了画布却没动静" case); the handoff now puts it into a run queue that drains the moment the active run finishes, and the real-time watcher counts a queued canvas as success so a retry cannot build duplicate canvases. Verified: with a three-node blocker run active, the takeover returned `queued:true`, and when the blocker finished the queued run started automatically and finished `done`.
- **Transcript noise is not a request.** Lines that are entirely bracketed markers (`[Request interrupted by user for tool use]`) were being taken over as if the user asked for them, creating idle canvases; they are now filtered out of ask discovery and the watcher. Harness 6/6.

- **Real-time takeover.** The takeover panel now has a 实时接管 switch: the server watches the active agent session (globally newest Claude Code transcript, or a pinned file), and every new real user request automatically creates a canvas, arranges the work and starts a run. Tool results, system injections and "继续/好的" are ignored; a request must be stable for 4 s before firing; when a run is already active the watcher backs off (15/30/60/120 s) and retries after it finishes. The watch state persists across server restarts and VS Code reloads, and the last existing ask is baselined so history is not replayed. Verified end to end: appending a request to a session file produced a new canvas whose working directory was the session's project and a run that finished `done`; the UI toggle passed 8/8; state survived a restart.
- **Tool-using runs no longer die on the rate budget.** A 7-task takeover run with tools hit the default 60k tokens/minute cap and failed C2–C5 with `budget exceeded`. Defaults are now 400k total / 250k per model / 250k per minute, and a rate violation is a warning instead of a hard abort (run/model caps remain hard). A four-node parallel tool run completed `done` with 10 tool calls and zero rate events.
- **Acceptance now sees what the node actually did.** The judge receives per-task tool evidence (`read_file×2`, `write_file×1`), so criteria like "调用了 read_file" are judged on real calls instead of whether the answer mentioned the tool; a short final answer is allowed when successful tool calls exist. The same four-node run then finished `done`, wrote four summary lines to `out.txt`, and no task failed.

- **Nodes can now use tools.** Every worker can call server-side tools: `read_file`, `write_file`, `list_dir`, `run_command`, `describe_canvas`, `get_canvas`, `list_workspaces`, `list_runs`, `get_run_result`, and `web_search`. The model only picks a tool and its arguments; the server validates paths/commands, executes, feeds results back, and loops up to six rounds. Sandboxed to the canvas working directory (the session's project for takeovers, settable per workspace), dangerous commands are refused, outputs are redacted, every call is audited, and `run.start` accepts `payload.tools = false` to disable them. Verified with a fake-adapter harness (9/9) and end to end on deepseek-v4-pro: the node read `note.txt`, wrote `out.txt`, the run finished `done` with acceptance 0.86, and `tool.called` events show both calls.
- **Providers can be disabled as a whole.** Kimi's account is suspended and Qwen/relay are unreliable, so 密钥与额度 now has a per-provider 停用/启用 toggle persisted in `model-policy.json`. Disabled families are excluded from the self-optimization roster, takeover candidate models and copied orchestrators, workflow planning, and key resolution (including env fallbacks). Verified: disabling moonshot/qwen/relay left the roster at deepseek + MiniMax + GLM, and a takeover arranged three nodes without a 502.
- **Canvas tabs scroll with the mouse wheel.** With many canvases the strip overflows horizontally; a wheel over the tab row now scrolls it sideways (native listener, non-passive). Verified in Chromium with 18 tabs.
- **Workflow failures show the server's reason.** The takeover note used to say only `HTTP 502` because the response body had already been consumed; it now reads the body once and includes the error text.

- **接管会话 takes over the session you are actually in.** With an empty project field, the server used its own start directory to locate Claude Code transcripts, so it could pick a weeks-old session from an unrelated project — the plan then worked on the wrong task, and nothing the user was doing got continued. Discovery now defaults to the globally most recently active session, reads project facts from that session's own `cwd`, and notes when an explicitly entered project differs. Verified: handoff picked the live session (age 0 min, 302 records) with project `e:\代码转视频` instead of the Nov 8 session under the server directory.
- **接管 runs the plan it produces.** Worker nodes are text-only models, so goals like "调用 mcp__qiansi__describe_canvas" used to become impossible tasks and the run aborted on acceptance. The planner now turns tool/MCP/file actions into a text deliverable plus an execution checklist, and the final node summarizes what is ready to execute. Re-ran the previously failing goal end-to-end: plan produced 「MCP 调用待执行清单」 + 一句话汇总, the run finished `done` in 39 s with acceptance score 1.0, and both nodes are `done` on the canvas.
- **Handoff no longer flashes console windows.** The git probes behind the duplicate-session/dirty checks spawned without `windowsHide`; under the VS Code extension host (which has no console) each call opened a visible console window. Hidden now.
- **接管后自动跳到新画布** when a run was started, so progress is visible immediately instead of leaving the user on the old canvas.
- **接管 failure modes are now visible and predictable.** A run that cannot start (409 run already in progress, 403 policy, 422 canvas not runnable, 503 missing credentials) returns its reasons/hint in `runError` and as a note instead of being swallowed. Unchecking 自动编排 disables 立即运行 (there would be no runnable nodes) and the server explains when a requested run was skipped. An archived (no-plan) canvas no longer renders a 去新画布 button. An explicitly entered project directory is now strict — no silent fallback to another project's session — and Codex sessions contribute their `cwd`; trailing separators are normalized before encoding. The planner also ranks the user's explicit task above the session/reference pack: the pack supplements facts but cannot replace the goal. `qiansi start` hides its detached console window.

- **Self-optimization is now a multi-model panel, not one voice.** Multiple models (one per configured vendor, up to five) read the same evidence through different lenses (correctness / adversarial / usability / evolution), then cross-examine each other: every candidate is confirmed, revised with corrected evidence/proposal/acceptance, or refuted; a flagship host merges duplicates and drops refuted candidates. Code changes get a second set of eyes too — a different model reviews the diff before the commit and can roll it back. Falls back to single-model reflection when only one model is available; panel size scales with level (L1 2 → L4 4) and can be pinned with `QIANSI_SELFOPT_PANEL` / `QIANSI_SELFOPT_MODELS`. The panel, stage strip and canvas nodes show who proposed each finding and the review verdicts. Verified with a fake-model harness (32 assertions: perspectives, refute/revise/merge, reviewer rollback, single-model fallback) and on real models through an isolated instance (panel deepseek-v4-pro + claude-opus-4-8[1M], 15.6k tokens, canvas `自省 · fixture` with 提出/互审 lines; UI 11/11).

- **Self-optimization runs on a canvas, on any repository.** Each session now creates its own canvas — 「自省 · <repo>」 — where the survey becomes a node and every discovered problem becomes an artifact node carrying its evidence, proposed fix, acceptance criteria and status (updated live as fixes are applied). The panel gained a project-path field, so the same survey → benchmark → reflect → apply → verify → snapshot loop can optimize any git project, not just Qiansi; the result view links straight to the canvas. Verified end-to-end on a separate fixture repo: one [high/bug] finding (off-by-one in findNote) surfaced as a node with its fix, on a canvas named after that repo.

- **Layout that survives a narrow panel.** The canvas tabs moved out of the toolbar into their own row; the toolbar measures itself and, below 860px, drops the brand subtitle and counters, and below 560px reorders itself so 接管会话 / 重载 / 运行编排 stay fully visible while secondary tool icons scroll. The canvas refits the graph (~250ms debounce) whenever its container changes size, so dragging the VS Code sidebar no longer leaves nodes off-screen.

- **One workflow = one canvas, with tabs and history.** Delegated tasks and handoffs now each get a fresh canvas named after the task instead of overwriting the one you are looking at. The workspace dropdown became a tab strip: running canvases show a pulsing dot, closing a tab archives the canvas into 历史画布 (soft delete), and history offers restore or permanent delete. `POST /api/workspaces/:id/archive|restore` added; `GET /api/workspaces` now carries `archivedAt` and a live `running` count per canvas.
- **接管会话 is a first-class toolbar button** (it was buried under 更多), and it actually starts work: handoff defaults to auto-run, passes the session task text straight to the canvas, skips the slow critique pass, and runs in the new canvas. Delegated runs no longer depend on the current canvas having an orchestrator set — one is synthesized from the billing strategy when missing.
- **Handoff reads the right thing.** Tool results were being mistaken for user requests (`role: user` also carries `tool_result` blocks, and transcripts can reach 100 MB), so a fixed 512 KB tail missed the latest ask entirely. The reader now scans backwards in chunks until it finds real text messages, and the workflow call falls back through every available model instead of two — one dead key no longer kills the takeover.

- **DSH plugin finalized (qiansi-dsh 0.1.1)**: one command installs it into a bootable DSH profile (`node dsh/qiansi/install.mjs --profile <name> --template headless`), because `dsh plugin add` on a fresh name initializes a base-only profile with no app. The installer now also adds the `@deepseek-ai/dsh-mcp-client` bridge explicitly — it declares no `dsh.bundle`, so it never becomes a profile layer and the patch's reference to it would otherwise fail to resolve. The status plugin's reachability probe no longer gives up after 1.5s (DSH's startup saturates the event loop and a live canvas was reported as down); it retries once and reports with a fallback path when the host has no logger. `QIANSI_DSH_DEBUG=1` mirrors the status line to stderr. Verified end-to-end: fresh profile → boot → `[qiansi] canvas reachable` + `[qiansi-mcp] ready`, and the same stdio invocation exposes 29 tools.

- **Auto-arrange sizes itself to the task** instead of always emitting 3–5 nodes: 2–3 for a single deliverable, 4–6 for research→write→verify work, 7–10 when the goal has several independent parts or needs multiple verification rounds. The planner and the critic both apply one test — "delete this node, which deliverable stops being produced?" — and the server caps rise to 10 nodes / 30 edges (12 subtasks per plan). The critic now also flags plans that are split too coarsely or padded to look complete, and the response says whether the plan was revised.
- **Auto-arrange now plans tasks, not roles.** Each generated node carries a one-line work order, a named deliverable (form + required contents) and 2–3 acceptance criteria that a third party can check independently; roles are how a task is carried out, not what gets split. The plan is then reviewed by the same orchestrator wearing a critic's hat, which looks only for overlapping responsibilities, uncovered parts of the goal, and criteria nobody can judge — on a revise verdict the corrected plan replaces the draft and the issues are surfaced in the UI. Deterministic guards back it up: duplicate node names get suffixes, missing criteria get concrete fallbacks, and every worker gets an explicit assign edge.
- The task's own deliverable and acceptance criteria now reach the worker prompt and the orchestrator's acceptance check, instead of one generic standard shared by every task.

- **Self-optimization**: Qiansi can now improve its own repository. Pick one of five modes (`repair` / `harden` / `polish` / `value` / `evolve`) and one of five levels (`L1` report → `L5` loop), and it runs survey → benchmark → reflect → apply → verify → snapshot: runs the repo's own typecheck/tests, reads git state and TODOs, searches the web for competitors and papers when the mode allows, asks a flagship model for evidence-backed findings, then applies each fix as a minimal exact-match edit, re-runs the checks, and commits it with a `selfopt/<hash>` tag. Any failure rolls that one change back.
- Token forecast for every run (`survey + benchmark + reflect + findings × per-fix`), calibrated against the median predicted/actual ratio of previous sessions of the same mode and level.
- Version index survives restarts: list versions, view the diff, `git checkout -B qiansi/version-<hash>` to switch, or return to the original branch. The worktree must be clean for anything that writes.
- Safety: git-repo-only, secret scan of the staged diff before every commit (refuses and rolls back on a hit), edits restricted to files listed at start, exact-match uniqueness checks, never pushes, one session at a time. Gated by the new Policy scope `selfopt.write`, audited on start/stop/finish/switch.
- Surfaces: 「更多 → 自我优化」 panel, `qiansi selfopt [--mode] [--level] [--budget] [--rounds] [--dir] [--status] [--versions]`, and the MCP tools `self_optimize` / `self_opt_status` / `self_opt_versions`.
- **Long-running projects**: `run.start` accepts `resumeOf` to continue a failed or interrupted run — only tasks without output are re-executed, completed outputs are injected as upstream context, and every resumed task carries a recovery note. Also exposed as the MCP tool `resume_project` and a 续跑 button on failed/interrupted rows of the Needs-attention panel.
- `autoResume` runs re-queue themselves after a failure or interruption (max 2 more rounds), including after a server restart; intentionally stopped runs are never auto-resumed.
- Leadership layer: the full judge defaults to a flagship model (`judgeModel` > orchestrator node model > `deepseek-v4-pro` > relay sonnet); each run ends with a flagship review (`verdict` / `score` / `suggestions` / `action`), and a multi-model discussion starts automatically when a task failed or the average acceptance score is below 0.6.
- Needs-attention inbox (`GET /api/attention`) aggregates pending approvals, judge `needsHuman` verdicts, failed runs and interrupted runs; the toolbar shows a badge.
- Upstream output pruner (threshold 8192 / head 4096 / tail 1024 chars) keeps deep chains from re-injecting whole earlier outputs; workspace-level standing instructions are injected into every worker prompt.
- Run records persist from creation; leftovers are marked `aborted` at boot; a side-effect ledger replays missing canvas write-backs and deliverables. `/api/admin/stop` and SIGINT/SIGTERM now shut down gracefully, and `qiansi watchdog [--interval 60] [--once]` supervises the server by exit code.

- Auto layout: the toolbar asks the orchestrator model for coordinates and falls back to a deterministic layered layout when the model or relay is unavailable.
- AI discussion: Ctrl/⌘ (or Shift) select two or more model nodes, give a topic, and each model speaks in turn with the full prior transcript; results can be saved as an artifact module.
- Task and artifact modules: run tasks and artifacts can be pulled out of the report onto the canvas, shown or hidden per module or from Settings.
- File modules: upload a file, get a node with a text preview, and wire it into any model or task as context.
- Region brush: drag a rectangle to create a subproject region; the mode (two-way, inbound, outbound, closed) gates which wires may cross the boundary.
- Node deletion is consistent across agent, task, artifact, file and region nodes, with a styled confirmation dialog.
- Node chat now calls the configured model through `/api/chat` instead of replying with a mock.
- Canvas persistence: node positions, wires, regions, task/artifact/file modules, hidden state and the chosen orchestrator are saved to `~/.qiansi/canvas.json` and restored on restart. Transient final-artifact nodes are not persisted.
- Drag membership: nodes, tasks, artifacts, files and libraries can be dragged into or out of a project region; membership is decided by the node center and the region gate still applies to crossing wires.
- Copy module: task and artifact modules can be duplicated from the inspector; copies carry their own output and do not affect the main flow.
- File library: a library node can hold many files, upload multiple files or a whole folder (relative paths preserved), and connect to several nodes. The auto-created public library connects to every model node and injects its file previews into node chat and AI discussion.
- Artifacts on wires: each task's output appears as a clickable chip on its source wire as soon as the task completes (not only at run end); an artifact module can be returned to its wire from the inspector, and pinned chips survive restart.
- File nodes and libraries can fan out to multiple targets; duplicate wires between the same pair are still rejected.
