# 接续 Agent 会话

2026-11-08。一个模块：**一键读取当前 agent 对话的上下文与项目内容，接着干**，并可选自动编排工作流。

## 它做什么

1. **读会话**：`~/.claude/projects/<编码目录>/<session>.jsonl`（Claude Code）或 `~/.codex/sessions/**`（Codex），只从**文件尾部读 512KB**（会话常达几十 MB），解析出用户最近的要求、agent 最近的结论、用过的工具、是否出现过错误。**没指定项目目录时读全局最新的会话**——你刚在哪个项目里和 agent 说话，就接管哪一段；项目事实也按该会话记录里的 `cwd` 读取，而不是服务端的启动目录。
2. **读项目**：git 分支与是否有未提交改动、`git ls-files` 前 60 条、package.json 的包名与脚本、README 前 2400 字。
3. **脱敏**：整份资料包在落盘前统一过 `redactSecrets`——会话里贴过 key 是常态。
4. **挂到画布**：写成一份 ≤ 数十 KB 的 Markdown，落到 `~/.qiansi/files/`，并挂到一个名为「接续上下文」的公共资料库节点（已存在则更新，不重复建）。
5. **自动编排（可选）**：把会话里最近一条要求交给 `/api/workflow`，让主控模型拆解成 2–10 个节点并连线；先试画布自己的主控，调不通时自动退到目录里可用的模型。工作节点是纯文本模型，规划规则要求：需要 MCP 工具 / 终端 / 本地文件的操作，不写成 worker 工单，而是产出「待执行清单」与文本交付。
6. **立即运行（可选）**：编排成功后可马上起一次 live 运行（走单运行互斥）；运行启动后界面自动跳到新画布，直接看进度。

## 实时接管

「接管会话」弹窗里新增 **实时接管** 开关：

- 开启后，服务端每 4 秒看一次当前 agent 会话（全局最新的 Claude Code `.jsonl`，也可以指定文件），
  发现**新的真实用户需求**就自动走一遍「新建画布 → 自动编排 → 立即运行」；
- 只认真正的用户文本：tool_result、系统注入、命令回显、整行方括号标记（如 `[Request interrupted by user …]`）都会被过滤；`继续`/`好的` 这类短指令也会跳过；
- 需求写入后稳定 4 秒才触发，避免用户还在打字时抢跑；
- 已有运行在跑时，新画布会**排队**：当前运行一结束自动开跑（实时接管把排队也算接管成功，不会重复建画布）；
- 状态落盘到 `~/.qiansi/takeover-watch.json`，服务重启或 VS Code 重载后自动继续监听；启动时把已有的最后一条需求记为已处理，不会把历史需求全部重跑；
- 接口：`GET /api/takeover/watch` 看状态，`POST /api/takeover/watch {enabled, sessionFile?}` 开关。

实测：在一份临时会话文件里追加「用一句话说明多模型协作的一个好处。」，监听器在数秒内发现，
自动创建画布（工作目录 = 会话项目）、编排、开跑，运行 `done`；重启服务后监听状态仍在。

## 失败归因与自动重试

接管与排队运行都带 `autoResume`。一次运行失败时：

1. **归因**：从 `task.failed` 事件里提炼失败任务数、原因分类（预算用尽 / 模型额度或密钥不可用 / 网络或超时 / 验收未通过）与前三条具体错误，存进运行记录（`failureSummary`）；
2. **自动重试**：从断点续跑（只重跑没有产出的任务），最多 2 次，即首跑 + 2 次重试共 3 次；达到上限后不再自动重试；
3. **呈现**：
   - 画布上出现「失败总结 · 第 X/3 次」卡片，写明原因与是否已排队重试；
   - 运行进度条下方显示失败结论、第几次尝试、具体原因，并给出「重试」按钮（手动续跑，不占用自动重试次数上限）；
   - `GET /api/runs/:id/result` 返回 `failureSummary` / `attempt` / `maxAttempts` / `autoResume`。

自动续跑请求必须带原工作区的 `x-qiansi-workspace` 头，否则会被 `resume_workspace_mismatch` 拒绝——这是之前「失败后不重试」的根因，已修复。

实测：用一个已停用的 Kimi key 跑必败任务，三次尝试全部失败；第一次失败总结 `attempt 1/3、retry:true`，第三次 `attempt 3/3、retry:false`；画布卡片列出 429 原文；界面上点「重试」会发起第四次手动续跑。

## 入口

- **界面**：画布工具栏的「接管会话」主按钮（不再藏在「更多」里），可选来源（自动 / Claude Code / Codex）、项目目录、任务原文、是否自动编排、是否立即运行；返回后显示读到的是哪条会话、多少条记录、多久以前、资料包大小、新增了哪些节点。
- **MCP**：`handoff_from_agent`（参数同上）。DSH / Claude Code / Codex 里的 agent 可以直接调用。
- **HTTP**：`POST /api/handoff`。

## 2026-11-12 修复

| 问题 | 原因 | 修法 |
|---|---|---|
| 接管后流程从未跑通 | 服务端按自己的启动目录找会话，读到的是两周前的旧会话；旧任务恰好要求 MCP 工具，worker 无法执行 | 默认读全局最新会话；项目事实跟会话 `cwd` 走；规划规则 14 把工具动作改写成待执行清单 |
| 弹出许多窗口又消失 | `git` 探测未设 `windowsHide`，VS Code 扩展宿主没有控制台，每次调用弹一个黑色控制台窗口 | 统一隐藏子进程控制台（含 `qiansi start` 的 detached 子进程） |
| 点完接管看不出发生了什么 | 运行在新画布上启动，但界面留在旧画布 | 运行启动后自动跳到新画布（1 秒后） |
| 勾了「立即运行」却没跑，也没有原因 | `run.start` 的 409/403/422/503 被空 catch 吞掉，`runId` 为 null 且不写 notes | 失败原因（`error` + `reasons` + `hint`）写进 `runError` 与 notes |
| 取消编排但保留「立即运行」 | 两个开关独立，运行被 `arranged.nodes > 0` 静默跳过 | 取消编排时禁用并取消「立即运行」；服务端也补一条说明 |
| 指定项目目录却接管到别的项目 | 该项目没有会话时回落到全机器最新会话；尾部分隔符还让目录编码对不上 | 指定目录时只读该项目的会话；编码前去掉尾部分隔符；Codex 会话也读 `cwd` |
| 明确写了任务，编排却按会话资料来 | 目标里无条件拼上了会话最后一段结论，资料包又很显眼 | 有任务原文时只用任务；规划提示明确「资料不能替换总目标」 |
| 编排失败的画布仍给「去新画布」入口 | 前端忽略 `archived` 标志 | 归档时显示「已保存到历史画布」，不再提供跳转 |

回归实测：用之前失败的 MCP 目标重跑——编排 2 个节点（「MCP 调用待执行清单」「一句话汇总」），运行 39 秒完成，验收 1.0，画布两个节点都是 `done`；接管选中的是当前会话（0 分钟前、302 条记录），项目 `e:\代码转视频`。

## 过程中修掉的两个真 bug

1. **自动编排“静默失败”**：`/api/workflow` 返回的是 `{ workflow: { nodes, edges } }`，我按顶层 `nodes` 读，永远拿到空数组，却只留下一句模糊提示。现在解析正确，且失败原因会写进返回的 `notes`（HTTP 状态或异常消息）。
2. **主控不可用就整段放弃**：编排沿用画布主控，主控走的中转断了就 502。现在先试画布主控，失败自动退到目录里可用的模型。

## 已知限制

- Codex 会话结构未完整核实，解析是尽力而为（解析不到就给空，并提示「未找到可读的会话记录」）。
- 会话只读尾部：一次超长工作最前面的决策不在资料包里。
- 自动编排复用 `/api/workflow`，会消耗一次主控模型的调用。
- 读取范围只覆盖 Claude Code 与 Codex 两家；其他 agent 需要新增适配。
