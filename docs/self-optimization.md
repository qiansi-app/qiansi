# 自我优化

牵丝可以拿一个 git 仓库当工作对象：自己跑检查、自己复盘、联网找竞品和论文、然后改自己，并把每次通过校验的改动留成可切换的版本。你只需要选两个旋钮——**模式**和**程度**——再给一个 token 上限。

入口三处：画布「更多 → 自我优化」、命令行 `qiansi selfopt`、MCP 的 `self_optimize`。

## 一轮做什么

```
体检 survey → 对标 benchmark → 复盘 reflect（评审团）→ 互审 critique → 执行 apply → 校验 verify → 快照 snapshot
```

| 阶段 | 做什么 | 花不花模型额度 |
|---|---|---|
| 体检 | 跑 `package.json` 里的 `typecheck` / `test`，读 git 状态、热点文件、TODO | 不花 |
| 对标 | 联网找竞品与论文（只有 `value` / `evolve` 模式会做） | 少量 |
| 复盘 | 多个模型各带一个视角，独立产出问题清单 | 主要开销 |
| 互审 | 每位评审逐条确认 / 修正 / 驳回别人提的问题，再由主持人合稿 | 主要开销 |
| 执行 | 逐条把问题落成最小改动 | 主要开销 |
| 校验 | 改完立刻重跑检查，不通过就把这一条回滚；另换一个模型复核 diff | 少量 |
| 快照 | 通过后提交并打 `selfopt/<hash>` 标签，记进版本索引 | 不花 |

## 评审团：多模型视角 + 互审纠错

复盘不再是一个模型自言自语。每个有 key 的厂商最多取两个模型，凑成一支评审团（L1 两位，L2/L3 三位，L4 四位，L5 三位），每位被分配一个视角：

| 视角 | 找什么 |
|---|---|
| 正确性 | 真实报错、崩溃、逻辑错误、回归、类型漏洞 |
| 对抗 | 假设实现是错的：边界值、竞态、失败路径、安全与资源问题 |
| 体验 | 误导的提示、缺失的空状态、文档与实现不一致、重复劳动 |
| 演进 | 结合最近改动、TODO 与对标，该做而未做、做了却半途而废的事 |

流程是三步：

1. **独立复盘**：所有评审同时阅读同一份证据，各自产出候选问题（并行调用，任何一位失败不影响其他人）；
2. **交叉质询**：每位评审逐条检查别人提的候选，给出 `confirm` / `revise` / `refute`；被全体评审驳回的候选丢弃，`revise` 修正的依据、改法与验收直接覆盖原候选；
3. **综合合稿**：由第一位评审（旗舰模型）合并重复项、按证据强度排序，输出终稿；被驳回的候选默认不恢复，除非主持人能在证据里写明驳回理由为什么站不住。

执行阶段同样有两双眼睛：实现者改完后，**换一个模型**只看 diff，判断是否只动了相关行、有没有引入新错误、是否满足验收。复核明确说 `ok:false` 就回滚这一条，不提交。

**只有一个可用模型时**，互审与综合自动跳过，退回单模型复盘；这会在日志与阶段条里写明。想让评审团换人，可以：

```powershell
$env:QIANSI_SELFOPT_MODELS = "deepseek-v4-pro,glm-5.3-flash,kimi-k2.7-code"   # 指定成员
$env:QIANSI_SELFOPT_PANEL = "3"                                                # 或只调人数
```

某个指定模型不可用（key 失效、正文为空）时，会自动换下一家并把「谁代答」写进日志，不会让整轮失败。


## 模式：做多大范围

模式是一个逐级放宽的白名单——每一档允许处理的**问题类别**写在 `kinds` 里，复盘提示把这组类别交给模型，模型给出清单后，服务端再按白名单过滤一次。模式名本身不构成授权。

| 模式 | 处理范围 | 明确不做 |
|---|---|---|
| `repair` 修错 | 类型错误、失败测试、崩溃、明显缺陷 | 不改架构、不动依赖、不联网 |
| `harden` 加固 | 修错 + 安全边界、输入校验、失败路径、性能退化 | 不改对外行为、不改界面 |
| `polish` 打磨 | 加固 + 错误提示、空状态、文档、重复代码 | 不新增功能模块 |
| `value` 增值 | 打磨 + 联网对标竞品、定位与增长差距 | 不编造市场数据、不做需要后端的承诺 |
| `evolve` 探索 | 增值 + 读论文、做隔离小实验 | 实验不达标就丢弃，不合并未验证的东西 |

## 程度：走多远

| 程度 | 行为 | 写文件 | 提交 |
|---|---|---|---|
| `L1` 巡检 | 只出报告 | ✗ | ✗ |
| `L2` 建议 | 报告 + 每条问题的具体改法（不落盘） | ✗ | ✗ |
| `L3` 小步 | 自动改低风险项，单条最多 3 个文件 | ✓ | ✓ |
| `L4` 深改 | 允许跨文件重构，单条最多 12 个文件 | ✓ | ✓ |
| `L5` 持续 | 改完一批再复盘一批，直到预算或轮数耗尽 | ✓ | ✓ |

`L5` 的熔断有三个：预算用尽、达到 `maxRounds`（默认 3，上限 8）、本轮一条都没应用成功。

## 预算预测

估算按结构化成本拼：

```
每位评审复盘 9000，共 N 位
互审 = N × 2500 + 综合 6000（只有 N ≥ 2 时）
每轮 = 体检 1500 + 对标（模式需要时 6000）+ 复盘 N×9000 + 互审
     + 建议（仅 L2：问题数 × 2500）
     + 实现（L3 每条 9000 / L4 每条 14000 / L5 每条 10000）
     + 复核（写代码档每条 1200）
期望 = 每轮 × 轮数 × 历史校准系数
区间 = 期望 × 0.6 ~ 期望 × 1.7
```

历史校准：每次会话结束会在 `~/.qiansi/selfopt/<仓库哈希>/journal.jsonl` 记一行「预测 vs 实耗」，同「模式 × 程度」组合的历史比值取中位数，夹在 0.4–3 之间后参与计算。第一次跑没有历史，系数是 1。

预测高于预算时界面会标红，但不会拒绝启动——`L5` 会在预算处提前收尾，`L1`–`L4` 只跑一轮。

## 版本与切换

每次通过校验的改动都是一个独立提交：

- 提交信息 `selfopt(<mode>/<level>): <问题标题>`，正文带问题 id、依据与验收标准；
- 标签 `selfopt/<hash>`；
- 索引 `~/.qiansi/selfopt/<仓库哈希>/versions.json`（问题、文件、token、会话 id、基准提交与分支）。

界面里每个版本可以「查看」（`git show` 的前 24KB）和「切换」（`git checkout -B qiansi/version-<hash> <提交>`，不动原分支）；「回到原分支」把你放回开关。

## 安全边界

| 边界 | 做法 |
|---|---|
| 只在 git 仓库里跑 | `git rev-parse --is-inside-work-tree`，否则直接拒绝 |
| 工作区干净才改代码 | `L3` 以上遇到未提交改动返回 `worktree_dirty`；`L1`/`L2` 只读，允许脏 |
| 密钥不进仓 | 提交前扫暂存差异，命中 `sk-*`、`AKIA*`、`ghp_*`、私钥头、`server-token` 等即中止并回滚 |
| 不越出仓库 | 改动路径必须落在开始时给定的文件清单内，且逐条校验 `oldText` 只出现一次 |
| 失败必回滚 | 校验失败或改动写入异常，立刻 `git checkout --` 这一条涉及的文件 |
| 不自动推送 | 版本只留在本地提交与标签上，`git push` 从不执行 |
| 单人单轮 | 同一时间只允许一个会话；并发请求返回 `selfopt_in_progress` |

权限走 Policy 的新 scope `selfopt.write`：默认人类账户与通配 agent 都有，`acceptMode: off` 时未具名 agent 会被拦下。拒绝与放行都写进 `audit.jsonl`。

## 用法

界面：「更多 → 自我优化」→ 选模式和程度 → 看预测 → 开始。跑的时候阶段条会亮，问题逐条出现。

```powershell
qiansi selfopt --mode value --level L1 --budget 120000      # 先看报告
qiansi selfopt --mode repair --level L3 --budget 80000      # 真的改
qiansi selfopt --mode harden --level L5 --budget 300000 --rounds 4
qiansi selfopt --status
qiansi selfopt --versions
```

MCP：`self_optimize` 发起，`self_opt_status` 看进度，`self_opt_versions` 列版本 / `diff_id` 看差异 / `switch_id` 切换 / `restore` 回原分支。

## 已知限制

- 一轮最多 4 条问题（`L1`/`L2` 6 条），单条实现只拿到目标文件的**开头 8KB**；超长文件可能改不准，此时校验会拦下。
- 评审团让模型调用数变成 N 倍（含互审与综合），预算预测已计入；预算不够时互审会提前收尾并沿用候选清单，不会丢结果。
- 「评审团」成员取自**有 key 的厂商**，不探测 key 是否有效。key 失效时会在日志里写明由谁代答，实际多样性可能低于名单；想让某几家优先参与，用 `QIANSI_SELFOPT_MODELS` 指定。
- 复查依赖仓库自己声明了检查命令。没有 `typecheck`/`test` 脚本时会退回 `npx tsc --noEmit`；连 `tsconfig.json` 都没有就没有校验，只有密钥扫描与模型复核兜底。
- 会思考的模型可能把输出预算全花在推理上、正文为空。这条路径会自动换下一家模型重试；换完还空就记为「复盘输出无法解析」，本轮跳过而不是乱改。
- 设计规格本身也是牵丝的多模型画布跑出来的（4 节点、48,463 tokens），原始产物在 [dogfood-2026-11-10/](dogfood-2026-11-10/)。其中 C4 的「最强反对论证」指出的问题——模式名不等于行为边界、首轮预测不可靠——对应的就是上面的 `kinds` 白名单和历史校准。
