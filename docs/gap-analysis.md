# 竞品差距可行性评估

2026-10-26。评估口径固定为：**单人开发、本地优先、无云后端、无运维、Windows 桌面为主**。结论一律按这个口径给，换口径结论会变。

八份调查都是只读代码审计，每条结论都能指到 `file:line`。完整原始结论在会话记录里，这里只留判断。

---

## 一、结论表

| 差距 | 完整形态 | 在现有条件下的结论 | 可裁剪出的最小集 | 最小集工时 |
|---|---|---|---|---|
| 一键发布成服务 | Dify / Coze 的「发布应用」 | 对外发布不建议；**运行结果契约值得先做** | 运行返回结构化结果 + 产物回写画布 + 不可运行画布返回 422 | 2 天 |
| RAG 知识库 | Dify 的向量检索 | 全量收益低；**最小集值得做** | 上传文件全文可读 + 进真实运行的上下文 | 1 天 |
| 企业能力 | SSO / RBAC / 审计 | 企业级不做；**本地审计值得做** | audit.jsonl + 只读 token + 审批落盘 | 3 天 |
| 定时与事件触发 | n8n 的触发器 | 可做但收益低 | 进程内 setInterval + triggers.json + 复用 run.start | 3 天（含 UI/重试 5 天） |
| 模板市场 | n8n 模板库 | 可做但收益低 | 画布 JSON 导入/导出 + 从链接安装 | 2–3 天 |
| 移动端 | 全功能手机版 | 可做但收益低 | 只读导出页（已被 P0 的导出覆盖一半） | 1 天 |
| 多人协作 | Figma 式实时协作 | 不建议做 | SSE + 操作流同步内核可单做 | 同步内核 1–2 天，完整 10 天 |
| SaaS 集成 | n8n 的上千连接器 | **不建议做** | 无 | — |

一句话：**八项里没有一项能按原形态成立，能成立的都是裁剪版；而裁剪版里最值钱的三项，其实不是新功能，是补现有功能的窟窿。**

## 二、调查顺带挖出来的三个真断点

这三条比任何一项市场型功能都重要，合计约 3 天。**三条都已在 2026-10-26 修完并验证**，下面是原始判断与修法。

### 1. 画布驱动 live 运行，没有任何端到端证据 ✅ 已修

代码已经能由画布生成计划（`apps/server/src/plan-from-canvas.ts`），但：

- `~/.qiansi/runs/` 里三次真实 live 运行，计划全是硬编码的 `livePlan`，没有一次是「由画布生成」。
- 画布不满足运行条件时（worker 少于两个），`apps/server/src/index.ts:1028` 会**静默**退回硬编码计划，调用方看不出区别。
- 跑完之后，服务端不把产物写回画布。牵丝界面里能看到产物，是因为渲染进程自己订阅了 SSE 并在前端补写（`apps/studio/src/App.tsx:2090`）——**从 agent 或 headless 触发的运行，产物永远不会出现在画布上**。

### 2. 上传的库文件根本没进真实运行 ✅ 已修

- 库节点被 `plan-from-canvas.ts` 的 `NON_WORKER_KINDS` 排除，不参与计划生成。
- 上传时只把前 1200 字存成 `preview`（`apps/server/src/index.ts:709`），运行时的 `run.start` 也不携带文件。
- 结论：文件目前只在节点自己的对话里生效，画布级的「把资料喂给整张图」是半成品。

### 3. 一枚全权 token 撑起所有入口 ✅ 已缓解

- `/api/bootstrap` 不带任何鉴权就发全权 token（`apps/server/src/index.ts:277`）。
- MCP server 读的是同一枚 token（`packages/mcp/server.mjs`），能写保险库、能调 `/v1`、能改画布。
- 一旦按「移动端」或「发布」的思路把监听地址改成 `0.0.0.0`，同网任何人都能拿到这枚 token。**这两项如果要开，必须先把只读/受限 token 做出来。**

## 三、本轮已修的相关问题

三条断点的修法与验证：

| 断点 | 修法 | 验证 |
|---|---|---|
| 画布静默退回演示计划 | 不可运行时返回 **422 + 具体原因**；只有显式传 `allowDemoFallback` 才用内置计划 | 单节点画布实测 422，返回「至少需要两个带模型的节点」 |
| 产物不回写画布 | 服务端在 `run.finished` 时按 `assignedNodeId` 把产物写回节点；`/api/runs/:id/result` 提供结构化结果，MCP 新增 `get_run_result` | 单测 17 项断言全过；MCP 实测 run → get_run_result 拿到逐任务产物 |
| 库文件进不了运行 | 运行时从 `~/.qiansi/files` 读回文本文件（跳过二进制、单文件 24KB、按任务数分摊 80KB），注入子任务描述 | 单测验证文件内容出现在子任务描述里、二进制被跳过 |
| 全权 token 一把通吃 | 新增只读令牌 `server-token-read`（仅 GET）；`audit.jsonl` 记录画布写入、运行、保险库与审批；审批记录落盘 | 只读令牌 GET 200 / POST 403；审计查到 3 条记录；重启后审批仍可读 |

顺带修掉的：
- 打包版每次启动随机端口，插件和 hook 写死 8787 会静默连不上。现在服务端把端口写到 `~/.qiansi/server-port`，MCP 与 hook 按「环境变量 → 端口文件 → 8787」解析；非默认端口 8899 实测通过。
- MCP server 在启动时缓存 token，应用一重启就 401。改成每次请求现读。
- `~/.codex/启动Codex.bat` 里的明文 key 已移除，改为要求 `OPENAI_API_KEY` 环境变量，缺失时明确报错。

### 独立复核又抓到的（已修）

三个只读审查员对这批改动做对抗式复核，确认并已修复：

- **运行前没把画布刷到服务端**。保存有 800ms 防抖，点运行太快就会按旧版本生成计划，甚至被误判为不可运行。现在点运行先强制保存一次；若服务端已有更新版本（agent 刚改过），停下来让用户确认再跑。
- **反向同步会吞掉运行时节点**。整盘替换时 `__final__` 产物节点和它的边会消失，运行一结束产物卡片就没了。现在应用远端快照时显式保留这两者。
- **结果契约里的任务状态永远是 pending**。存储的计划从不回写状态，现在按「有没有产物 + 运行终态」推导。
- **没设主控的画布照样起跑**。计划生成器与诊断器判定不一致，导致「没有主控」这条理由永远不出现；现在两边一致，会返回 422。
- **一个任务失败就全标失败**。现在成功的任务保持 done，只有没产出的才标 failed。
- **文件预算按字符算**，中文会超三倍；改为按 UTF-8 字节，并改用磁盘上的真实文件名判断是否文本（防止二进制改名混进来）。
- Codex 示例配置把端口钉在 8787，绕开了端口文件；已去掉。
- **整盘替换会吞掉未提交的编辑**：轮询现在会跳过「本地有未落盘改动」的时刻；409 改成合并——保留你当前的画布，只吸收你本地没有的节点与连线，再用服务端版本号重试一次。
- **两次 live 运行会互相覆盖产物**：服务端加了单运行互斥，第二次提交返回 409 `run_in_progress`。

## 四、下一步
前三项（运行结果契约+回写+422、库文件进运行、审计+只读令牌+审批落盘）已于 2026-10-26 完成，验证记录见上一节。

**唯一还没验证的一环**：真实的 live 画布运行（会花钱调模型）。当前只验证到「计划由画布生成」，以及 demo 模式的 run→result 闭环。建议第一次真实运行时用最小预算，并确认 `GET /api/runs/:id/result` 里 `planSource` 是 `canvas`。

完成这三项之后，定时、模板、移动端才值得做——它们的价值现在有承载了：定时的是一次会回写产物的运行，模板是一张能跑出结果的图，移动端看到的是一块会自己更新的画布。

SaaS 连接器、向量 RAG、实时多人、SSO/RBAC 明确不做。这与 `docs/roadmap.md` 已有的「明确不做」清单一致；`docs/positioning.md` 把它们写成 P1/P2 是上一版的口径，以本文件为准。
