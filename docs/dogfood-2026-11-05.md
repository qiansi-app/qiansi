# Dogfood：用牵丝跑一场竞品研究

2026-11-05。命题：**用牵丝自己实施一次竞品对比研究**（8 个竞品、多模型分工），检验实际可行性，与「上一轮由单个 AI 直接调研」的产物对比优劣，并把暴露出的问题当场修掉。

资料抓取由外部 agent（Claude Code）完成——牵丝的 worker 是纯模型调用，没有联网能力，这本身就是要检验的第一条边界。8 份带来源的竞品简报（n8n / Dify / Coze / Flowise / Langflow / ComfyUI / Sim / 框架系画布）由 8 个并行研究员产出，合并成 16.6KB 资料包后注入画布，之后的审核 → 对照矩阵 → 机会分析 → 定位建议全部由画布上的四家模型完成。

八份原始简报在本机 `qiansi-dogfood/briefs/`（工作目录，不入库）；本轮四份最终产物在 [dogfood-2026-11-05/](./dogfood-2026-11-05/)。

## 一、六轮运行：四次失败各打出一个真 bug

| 轮 | 运行 | 结果 | 根因 | 当场落地的修复 |
|---|---|---|---|---|
| 1 | `7986a2f6` | 全灭，0 token | Kimi Key **余额不足被暂停**（429 suspended） | 审核员换智谱（产品无法替用户充值，但 429 的错误信息现在会原样透传） |
| 2 | `f0d8619a` | C1 两轮被掐 | **45s 任务超时**：GLM 思考 5398 条推理流后被硬掐 | 超时 45s → 120s |
| 3 | `862008ed` | C2 空产出 | 思考烧光 **4096 输出预算**，答案没地方写 | 各家族 maxOutput 4096→16384，编排器输出预算 →12288 |
| 4 | `e78b7a74` | C2 又被掐 ×2 | 120s 仍不够 GLM 想完全图最重的矩阵任务 | 矩阵员换 deepseek-flash；**并发 1→3**（独立支线并行） |
| 5 | `492ccf10` | 并行成功，C2 仍灭 | **deepseek-v4-pro 也是思考型**：240s 内流出约 3 万字符推理、0 字正文，且方言是 `none` 无法叫停 | 矩阵员 → deepseek-flash（闸门实测秒回）；超时 →240s |
| 6 | `2065d872` | ✅ **4/4 全绿** | — | — |

并发在轮 5 得到验证：C2（DeepSeek）与 C3（MiniMax）真并行，C3 只用了 20 秒。

**由此确认的产品短板（均已修）**：

1. `filesForTask` 的 `taskIndex` 参数从未被使用——多任务时所有任务拿到同一批文件的前 N KB，超出预算的资料永远进不了任何任务。已改为：放得下就全量给每个任务；放不下按任务轮转切片，集体覆盖全包。
2. 思考型模型在重提示词下会「想到没有答案」。已接上 GLM 的 `glm-thinking` 方言（节点 effort=off 即可关思考）；空产出时的重试从**升档**改为**降档**（越想越没地方写答案）。
3. MCP 没有「上传资料文件」工具——agent 用户想喂资料只能像这次一样绕道 HTTP。已加 `upload_file`（上传 + 可选挂到资料库节点），同步进 Claude Code / Codex 插件副本。
4. 单任务固定超时对轻重任务一刀切。本轮用全局 240s 缓解，按节点超时记入待办。

## 三、产物质量：交叉审核抓到了「我」的错

最有价值的证据来自审核员（C1）。资料包由外部 agent 机械压缩生成，审核员列出 18 条可信度问题，其中三条正是**压缩器自己的错误**：

- 第 17 条：多处来源 URL 和引文在「…」处被截断——这是资料包合并脚本按字节裁剪造成的，单模型自查几乎必然漏掉自己刚写的东西；
- 第 3 条：star 数一处写精确值、一处写 145k，口径不一致；
- 第 1 条：frameworks 节「可视化编排生态位实际空缺」与包内其余 7 个在营画布竞品直接矛盾——正确指出该论断应缩限为「框架生态内无画布」。

定位建议员（C4）的产物质量同样超出预期：三条劣势具体到可与竞品逐一对照（子工作流复用、节点级追踪、HITL 断点），Top3 建议每条附可验收标准，并主动声明「未引用资料包中未核实的精确数字」。

## 四、优劣对比：牵丝编排 vs 单模型直接调研

上轮竞品分析（`gap-analysis.md`、`positioning.md`）由单个 AI 一次性直接写出。同一命题两种做法的对照：

**牵丝赢的地方**

| 维度 | 证据 |
|---|---|
| 交叉审核 | 审核员抓到压缩器自己的截断错误与论断矛盾——单一模型自查自身的产出，这类错误最容易漏 |
| 可审计 | 每条验收带 gate/置信度、运行记录带 mandate（谁批准、按哪个策略版本）、产物挂图可回溯；直接调研没有留痕 |
| 判断多样性 | 四家模型独立作答，错误不相关；结论不是一口之声 |
| 可复用 | 这张图 + 资料包留下即模板：下个季度换 8 份新简报一键重跑；直接调研是一次性人工 |
| 成本透明 | byModel 分账（上表），5.1 万 token 明细到每个任务 |

**直接调研赢的地方（诚实清单）**

| 维度 | 说明 |
|---|---|
| 联网 | 牵丝 worker 不能上网，资料抓取仍需外部 agent；「扔个题目全自动出报告」的闭环不成立 |
| 前期成本 | 六轮才全绿，四轮失败暴露的全是产品健壮性问题——这些问题直接调研根本遇不到，因为根本没有执行层 |
| 墙钟 | 从第一次点火到全绿约 40 分钟（含调试）；直接调研一遍写完 |
| 输入深度 | 8 份简报必须压到 16.6KB 才能进上下文，矩阵员只见摘要；直接调研读全文 |
| 验收语义 | 「完成」只代表通过通用验收标准，矩阵的准确性仍需人复核（审核员的清单就是给人复核用的） |

**结论**：牵丝适合**结构已知的重分析与需要交叉验证的结论**——分工图是资产，资料可换，验收留痕；不适合探索性研究（无联网）与一次性轻任务（前期调试成本摊不平）。这与 [positioning.md](positioning.md) 的判断一致，但这次是拿运行数据验证过的。
