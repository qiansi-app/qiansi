# Key 计费类型与路由策略

2026-11-09。Key 分两种计费：**订阅**（包月/包周期，已付费，余额内边际成本≈0）和**按量**（每次调用都计费）。工作流设计时按策略选家族。

## 三种策略

| 策略 | 排序规则 | 适合 |
|---|---|---|
| 性能优先 `performance` | 按家族旗舰档从强到弱（relay > openai > deepseek > moonshot > zhipu = minimax > qwen） | 效果第一，不在乎花哪张卡 |
| 订阅优先 `subscription` | **有余额的订阅 Key 最前**（同类里挑更强的），其余按性能排 | 订阅已经付过了，先用掉 |
| 成本优先 `cost` | 按每百万 token 的**边际花费**从低到高；订阅且有余额记 0 | 尽量少花钱 |

没有余额的家族在任何策略下都排最后，不会被选中。

## 它在哪里生效

1. **运行前改派**：某个家族额度用尽（或不足一个任务）时，任务按策略改派到下一个可用家族；改派原因写进计划说明与审计（例：`deepseek 额度已用尽；按「subscription」改派到 zhipu：订阅 Key（边际成本 0），性能档 0.80`）。
2. **接续会话的自动编排**：交给工作流生成器的模型列表按策略排序，主控优先选订阅家族。
3. **运行记录**：`run.start` 审计里带 `strategy` 与 `keys`（每个家族用的是哪个 Key）。

每次运行也可以临时覆盖（`run.start` 的 `payload.strategy`），不改全局设置。

## 怎么改

**界面**：更多 → 密钥与额度。顶部三个策略按钮（当前生效的高亮）；每个 Key 右侧「标为订阅 / 改按量」切换计费类型，行内直接显示 `订阅` / `按量` 徽标。

**接口**：

```bash
# 全局策略
curl -X PUT /api/keys/strategy -d '{"strategy":"subscription"}'

# 标记计费类型
curl -X PATCH /api/keys/zhipu/default -d '{"billing":"subscription"}'
```

## 验证

- 路由单测 8/8：三种策略的排序、已用尽家族永远垫底、解释文案。
- 集成测试 6/6：同一个「起点家族没余额」场景，订阅优先改派到订阅家族（deepseek）、性能优先改派到 relay、成本优先改派到订阅家族；策略与计费类型都跨实例持久化。
- 接口：`PUT /api/keys/strategy` 返回新策略；`PATCH /api/keys/:slot/:id` 改计费后再次 GET 可见。
- 界面：面板里三选一（订阅优先高亮），每个 Key 有计费徽标（`qiansi-dogfood/keys-strategy.png`）。

## 设计取舍

- **性能档是粗排序**，写死在 `routing.ts` 的 `FAMILY_PERFORMANCE` 里，一个家族一个数。刻意保持可解释——换模型只改一个数，而不是引入一套评分。
- **订阅不等于免费**：订阅 Key 也有额度，用尽后自动轮换到下一个 Key 或按策略改派，逻辑与按量一致。
- **预估单价**沿用 `quota.ts` 的价目表（可覆盖），只用于排序与估算，不参与计费。
