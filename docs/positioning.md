# 牵丝的定位：用户需求、操作模式与竞品对照

写于 2026-10-26。这份文档回答四个问题：不同用户来牵丝是为了什么、他们各自怎么操作、同样的事竞品怎么做、以及我们哪些地方满足不了。

---

## 一、一句话定位

**牵丝是一张「能跑起来的流程图」：图本身就是程序，产物挂在连线上，跑的时候多个厂商的模型按图分工。**

它不和 Claude Code 抢「写代码」，不和 n8n 抢「连应用」，也不和 Dify 抢「上线一个 AI 应用」。它解决的是中间那层——**一次有多个模型参与、需要给人看清楚谁做了什么、结果要对得上号的任务**。

---

## 二、六种需求，六种操作模式

用户不是「用户」，是六种很不一样的来意。每一种对应一条最短路径，产品要保证这条路径不超过四步。

### 模式 A：一次性的重活（写报告、做分析、出脚本）

> 「我要一份 2000 字的调研，别糊弄我。」

1. 点「一键生成工作流」，点一个模板（调研报告 / 长文写作 / 竞品分析…），补上主题。
2. 选主控与工作模型 → 生成。画布上瞬间出现「主控 → 研究员 → 写手 → 审校」的图。
3. 点「运行编排」，看每个节点依次点亮、连线上的产物卡片一张张出现。
4. 不满意就点某个节点的「重跑」，只重跑那一段，不用从头来。

**关键价值**：能看见哪一步塌了。单模型对话框里，你只知道「结果不太好」；这里有具体节点、具体产物、具体验收理由。

### 模式 B：把一堆资料喂进去（研究、尽调、读论文）

> 「这 12 份材料和 3 个文件夹，帮我理出结论。」

1. 把文件/文件夹拖进「公共文件库」（自动传给所有节点），或给某个区域单独建文件库。
2. 用画笔圈出一个区域，画成「单向入」——资料只进不出，不影响主线。
3. 主控照常拆解，资料库作为上下文连到需要它的节点上。

**关键价值**：上下文是有位置的。哪份文件喂给了谁、哪个子项目是封闭的，在图上看得见。

### 模式 C：想复用大厂 agent 的对话能力（本轮新增）

> 「我在 Claude Code 里干活，但我想让它知道我的画布。」

1. 装插件（`claude plugin marketplace add …` + `install qiansi@qiansi`）。
2. 在 Claude Code 里随口提「画布」「工作流」「产物」——钩子自动把画布摘要塞进上下文。
3. 让 agent 直接改：「加一个审校节点，接到写手后面」——它在画布上真的加上了，牵丝界面 1.5 秒内自动刷新。
4. 想看图形就说一句，agent 把 SVG 贴回来。

**关键价值**：不重造对话体验。Claude Code / Codex 的对话、权限、工具生态照用，牵丝只做它们做不了的那块——**共享的、可视化的、多模型的状态**。

### 模式 D：团队对齐（评审、教学、汇报）

> 「我要让别人 30 秒看懂这套流程。」

「更多 → 导出画布」得到一个独立 HTML：图 + 文字摘要，双击就能开，不依赖牵丝运行。也可以让 agent 走 MCP 的 `export_canvas` 拿链接。

**关键价值**：交付物是图，不是一段说明文字。

### 模式 E：反复执行的固定套路（自动化）

> 「每周一把上周的竞品动态汇总一下。」

**这一块目前最弱**：没有定时触发、没有 webhook、没有失败重试队列。现在只能手动点运行。

### 模式 F：多模型互评（选型、交叉验证）

> 「这三个模型谁说得对？」

选中 2–5 个模型 → 「AI 讨论」→ 可以「复制模块」留档。产物节点会记住每一轮谁说了什么。

**关键价值**：分歧被记录下来，而不是被最后一个模型的回答盖掉。

## 三、竞品全景

四类，不是一类：

| 类别 | 代表 | 它们解决什么 |
|---|---|---|
| Agent 客户端 | Claude Code、Codex、Cursor、Windsurf | 一个人和一个 agent 的高强度对话与改代码 |
| 工作流自动化 | n8n、Make、Zapier、Pipedream | 把 SaaS 事件连起来，定时/触发/重试 |
| LLM 应用平台 | Dify、Flowise、Langflow、Coze | 搭一个可发布的 AI 应用（RAG、对话、API） |
| Agent 框架/编排 | AutoGen Studio、CrewAI、LangGraph Studio | 用代码编排多个 agent，附带图可视化 |
| 空间白板 | Figma FigJam、Heptabase、Freeform、Obsidian Canvas | 让人的思考有地方摊开 |

## 五、他们能满足、我们满足不了的（诚实清单）

按「会不会真的让人走掉」排序：

1. **定时与触发**（n8n / Make）。没有它，牵丝只能「打开来用一次」，不能「挂在后台天天跑」。这是我们从工具变成基础设施之间最大的缺口。
2. **SaaS 集成**（n8n 上千个节点）。用户想让画布去读 Gmail、写 Notion、发 Slack——现在只能靠 agent 用 CLI 绕。
3. **RAG 与知识库**（Dify）。公共文件库是「把原文塞进上下文」，不是「切片、向量化、按需检索」。文件一多就会撞上下文窗口。
4. **一键发布成服务**（Dify / Coze）。牵丝跑完就结束了，不能把这张图变成一个 API 或一个给客户用的机器人。
5. **多人实时协作**（Figma / Heptabase）。现在是一人一份本地文件。
6. **移动端 / 网页托管版**。完全没有。
7. **模板市场与社区**（n8n）。我们刚有 5 个内置模板，还没有「别人做的图我能一键导入」。
8. **企业能力**（SSO、审计、权限）。没有，也不打算短期做。

反过来说，**他们有而我们有的**只有一条，但这条很硬：**把多家模型的分工画出来、跑起来、把产物钉在链路上，并且能被 Claude Code / Codex 这类 agent 直接读写**。目前没有第二个产品同时做到这四件事。

## 六、差距收敛方案

原则：**先用「接入」换「集成」**。我们不做上千个 SaaS 节点，而是让已经会写代码的 agent 去调接口——牵丝提供图和状态，agent 提供手。这条路线下，P0 只有三件事。

### 已在本轮落地

| 项 | 状态 |
|---|---|
| 画布 HTTP API（revision 乐观锁、批量 ops、摘要、SVG、导出） | ✅ 已实现并端到端验证 |
| MCP 工具 10 个 + 资源 4 个 | ✅ 真实 Claude Code 会话中读写成功 |
| Claude Code 插件（上下文注入 hook、`/qiansi`、skill） | ✅ 安装、校验、真实会话验证通过 |
| Codex 配置与插件 | ✅ 文件就绪，hook 契约已在本机 codex 二进制确认 |
| 界面反向同步（1.5s 轮询 + 409 冲突接管） | ✅ 截图验证：页头 14→15 节点，弹出同步提示 |
| 画布导出（独立 HTML / Markdown） | ✅ 渲染验证通过 |
| 工作流模板（调研/长文/代码评审/竞品/短视频） | ✅ 界面验证通过 |
| `run_canvas` 的 goal 透传 | ✅ 已修（此前被丢弃） |
| **画布驱动真实运行**（节点→模型档案、连线→子任务、反向边不成环） | ✅ 已实现并单测：3 个节点推出三个厂商的档案，依赖关系正确 |
| 首次打开自动适配视图 | ✅ 已加 |

### P0（下一步，按此顺序）

1. **让 agent 改完就能看到运行结果**
   现在 agent 改完画布，还要用户回到牵丝点运行。补一个可见反馈：MCP 返回 runId 后，`qiansi://canvas/summary` 里带上「上次运行状态」，agent 可以轮询结果并直接向用户汇报。

2. **导出即分享**
   已有 HTML 导出。补：把导出页里的「生成时间」换成「一句任务目标」，并在图下面加每个节点的产物全文（可折叠）。这样它才是一份能发给别人的交付物，而不是一张图。

3. **运行前的可行性检查**
   画布现在会直接驱动真实运行，但用户改完图后不知道「这套配置跑不跑得起来」（缺 key、节点没连到主控、模型不支持所需能力）。在点运行前给一条检查结果，能省掉大量第一次失败。


### P1（一到两个月）

> 口径更新（2026-10-26）：下面这几项的可行性已逐条评估，结论见 [gap-analysis.md](gap-analysis.md)。定时触发 / 模板市场 / 移动端只值得做最小集；RAG 全量 / 多人协作 / SaaS 集成 / SSO 明确不做。

4. **定时与 webhook 触发**：在服务端加 cron 与 `/api/hooks/:id`，让图能挂后台跑。这是把牵丝从「工具」推到「基础设施」的那一步。
5. **文件库 → 轻量检索**：不做向量库，先做「按文件名/关键词切片召回」，把命中段落塞进上下文。成本低，能挡住大部分「文件太多」的抱怨。
6. **公共插件市场**：把 `plugin/` 发布到 Claude Code 的公共 marketplace，用户一行命令装。现在只能本地装。
7. **运行历史回放**：`/api/runs` 已有数据，UI 只展示本轮；把历史做出来，失败可以直接从历史里重跑。

### P2（想清楚再做）

8. 多人协作（要么做真同步，要么明确不做，中间态最糟）。
9. 发布为 API（会和 Dify 正面撞，除非定位成「把图暴露成本地 MCP 服务」）。
10. 移动端（只读视图可能是更好的答案）。

### 明确不做

- 通用 SaaS 集成（把这块让给 agent 和 n8n）。
- 通用 RAG 平台（做轻量召回就够了）。
- 代码编辑/IDE 能力（Claude Code / Cursor 已经做得很好，我们要做的是它们旁边那块屏幕）。

## 七、怎么判断做对了

不看 DAU，看三个数：

1. **一次运行里被使用的不同厂商模型数** ≥ 2（否则用户没必要用牵丝，单模型就够了）。
2. **产物卡片的点击率**（点开看某一步产物的人占比）——这是「可追溯」到底有没有价值的唯一证据。
3. **从 agent 侧写入画布的次数 / 从界面写入的次数**——这个比例往上走，说明「接入 agent」这条路走通了。
