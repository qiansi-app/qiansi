# 用户视角验收

2026-11-12。验收不再只问「模型觉得自己写得对不对」，而是像用户一样把项目真的跑起来：
打开页面、看画面、点按钮、换到手机宽度，截图留证，再逐项给结论。

借鉴 Grok Bot 团队的验证原则（见 [grokbot-lessons.md](grokbot-lessons.md)）：
**验证就是工作本身**；能机器判定的写成检查项，判定不了的用截图给人看。

## 它做什么

1. **识别项目怎么启动**：读工作目录里的 `package.json`——
   - 有 `vite` 依赖 + `dev` 脚本 → `npm run dev -- --host 127.0.0.1 --port <随机端口>`；
   - Next → `npm run dev -- -H 127.0.0.1 -p <端口>`；
   - 其他 `dev` / `start` / `preview` → 原样执行，从输出里识别实际网址；
   - 有 `dist` / `build` / `out/index.html` 或根目录 `index.html` → 用内置静态服务器（不用起依赖）；
   - Electron 主进程 → 明确报告「需要真实桌面窗口，自动验收只覆盖网页构建」。
2. **等页面可用**：轮询地址直到非 4xx/5xx；启动命令提前退出时把输出尾部一起报出来，而不是只留一句超时。
3. **无头浏览器打开**：使用本机 Edge / Chrome 的 `--headless=new`，通过 CDP 驱动
   （Node 24 自带 WebSocket，不引入 Playwright/Puppeteer）。
4. **检查（每一项都有用户能读的说明）**：

| 检查 | 判什么 | 判定 |
|---|---|---|
| 项目能启动并响应 | HTTP 状态 | 2xx/3xx |
| 页面有可见内容 | 可见文本 ≥12 字且元素 ≥8 个 | 空白页会被抓住 |
| 没有脚本报错 | 未捕获异常 + `console.error` | 忽略 favicon / sourcemap / HMR 噪音 |
| 本站资源都加载成功 | 同源请求失败或 ≥400 | 忽略 favicon 等 |
| 图片都能显示 | `<img>` 的 `naturalWidth > 0` | 列出坏图地址 |
| 有可点击的操作 | 可见 button/a/input 数量 | 至少 1 个 |
| 手机上不横向溢出 | 390px 宽下 `scrollWidth` | 溢出 ≤2px |
| 主要按钮有反应（软） | 点第一个按钮后 DOM 是否变化/跳转 | 只提醒，不否定整次验收 |
| 截到了真实画面 | 桌面与手机 PNG 体积 | 太小视为空白 |

5. **留证**：桌面 1440×900 与手机 390×844 两张 PNG，存到
   `~/.qiansi/user-view/<id>/`；报告 `report.json` 里带结论、逐项结果与页面可见文字。
6. **写回画布**：固定 id 的「用户视角验收」卡片，列出结论、逐项检查和截图路径。
7. **结束即清理**：无论成败都关闭浏览器并 `taskkill /T` 杀掉整棵启动进程树；
   用的随机端口，不会碰用户已经在跑的服务。

## 什么时候自动跑

一次运行 **`done`** 之后，如果这张画布**显式设置过工作目录**，并且识别为可启动的网页项目，
服务端会在后台自动做一次验收（最多 120 秒），结果直接落到画布卡片。
`run.start` 传 `payload.userView = false` 可以关闭。

失败时不会自动占用时间；失败面板里的「用户视角验收」按钮可以随时手动跑——
很多时候任务失败但页面其实能用，这个结果能帮用户判断该修流程还是修代码。

## 接口

- `POST /api/user-view`：`{ runId?, rootDir?, url? }`。给了 `url` 就只验收已有地址；
  否则按画布工作目录启动项目。返回 `{ ok, report }`。
- `GET /api/user-view/latest?ws=`：这张画布最近一次报告（按画布过滤后再取最新）。
- `GET /api/user-view/:id`：完整报告。
- `GET /api/user-view/:id/shot/desktop|mobile`：截图 PNG，界面弹窗直接显示。

## 界面

- 运行条右侧「用户视角验收」按钮：没有结果时触发，有结果时直接打开证据弹窗；
- 结果徽标按结论着色（通过=绿、未通过=红、无法验收=黄）；
- 弹窗：一句话结论、逐项检查、桌面与手机截图、页面上用户看到的文字、重新验收；
- 没有运行记录但有验收结果时，运行条位置保留一条窄条，刷新也不丢证据。

## 已经验过

- 模块级：正常页面 `pass`（9 项全过、点击按钮后页面变化）；故意抛异常且空白的页面
  `fail`（content / console / interactive / overflow / visual 全被抓到）。
- 接口级：12/13（唯一一条是我把「排队」误当成失败，实际行为正确）；
  截图端点返回 `image/png` 且 >8KB。
- 端到端：真实跑一轮工作流（DeepSeek，`done`）→ 服务端自动启动静态项目 →
  验收 `pass`、两张截图、画布卡片写入。
- 失败→重跑：一个因「产出过短」失败的运行，诊断显示失败原因和可重跑方式；
  「继续重跑」后 `done`，随后自动验收 `pass`（11/11）。
- 界面：失败条 + 诊断面板 + 用户视角弹窗 16/16；无运行的窄条 4/4。

## 已知限制

- 只自动验收网页项目；Electron / 桌面程序给明确原因，需要人工打开。
- 会真的执行项目里的 `dev` 脚本——这是它的用途，但只应对**自己的项目**使用；
  不需要联网的证据不进报告，截图可能包含页面上的任何内容。
- 只检查首屏与一个主要按钮；多页面、登录态、需要后端的流程还没覆盖。
- 需要本机装 Edge 或 Chrome；两者都没有时报告 `blocked`。
