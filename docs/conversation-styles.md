# 对话风格

同一件事，说法不同，结果差很多。牵丝把「怎么说话」做成可选项，落在两个地方：**节点干活的方式**和**多 AI 讨论接话的方式**。

## 九种风格与适用场景

| 场景 | 风格 id | 它对模型的要求 |
|---|---|---|
| 学新知识、理解概念 | `scaffold` 引导型 / 脚手架式 | 先确认已知，再分层讲解，每层一个例子，最后留检验问题 |
| 需要新点子 | `brainstorm` 头脑风暴式 | 先发散到 8 个以上，标注赌注/成本，发散阶段不自我否定 |
| 方案有风险要验证 | `debate` 辩论 / 魔鬼代言人 | 复述主张→最强反对论证（带反例）→成立条件 |
| 做选择题 | `converge` 收敛决策式 | 候选×判据对照表→明确推荐→放弃理由→最早出错信号 |
| 找人聊清思路 | `peer` 同行讨论式 | 平等交换、允许「我不确定」，可以不给结论 |
| 要一个能落地的方案 | `consultant` 顾问式 | 目标与约束→分步方案（产出/依赖/负责人）→验收标准→兜底 |
| 日常查资料、写东西 | `expert` 专家直答 / 精简式 | 一句话结论→要点→依据，不铺垫 |
| 情绪低落时 | `empathy` 倾听共情式 | 先准确复述处境与感受，再开放提问；不急着给建议 |
| 面试、谈判演练 | `roleplay` 角色扮演式 | 先声明角色与立场，全程保持角色，结束附三点评点 |

每种风格同时定义三件事（见 `packages/engine/src/styles.ts`）：

- `directive` —— 这个节点怎么组织输出；
- `handoff` —— 下游拿到的上游内容该保留什么、丢掉什么；
- `discussion` —— 讨论时怎么接别人的话。

## 在哪里用

**节点级**：点开任意模型节点的对话抽屉，底部有风格选择器（默认按角色推荐，例如「审校」会被推荐为辩论式）。选择写进节点数据 `style`，运行与重跑都生效。

**讨论级**：AI 讨论窗口的「风格」下拉，默认跟随主题自动推荐，手动选过之后不再自动改。

## 自动推荐

按角色/节点名里的关键词推荐，冲突时按固定优先级：

`roleplay > empathy > debate > converge > consultant > scaffold > brainstorm > peer > expert`

（例如「安全评审，给出落地建议」判为辩论，而不是顾问。）

没写 `style` 时，画布计划生成器会把推荐结果写进子任务；用户显式选择永远优先。

## 验证

- 单测 15 项：九个风格齐全、九类角色推荐正确、提示词含指令与交接规则、画布计划显式优先/自动推荐（`qiansi-style-check.ts`）。
- 真实讨论（`debate` 风格，deepseek-flash + MiniMax）：双方都给出反对论证与反例，且后者针对性反驳了前者的具体论点；接口回显 `style=debate`。
- 界面：Electron 真实点击模型节点，抽屉里出现 9 个风格选项（截图 `qiansi-dogfood/style-inspector.png`）。
