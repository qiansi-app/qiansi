- 验收标准：紧扣任务目标，给出可直接使用的完整答案；不确定的地方明确标注，不编造来源或数字。

# 牵丝 Qiansi 自我优化功能规格

## 一、模式体系

| 模式 | 适用范围 | 做什么 | 不做什么 |
|---|---|---|---|
| 只修报错 | 编译错误、测试失败、运行时崩溃、明确异常 | 定位并修复明确报错；补回归测试；保持行为不变 | 不改非报错路径；不重构；不改 UI/文案；不升级依赖 |
| 加固健壮性 | 边界条件、异常处理、类型安全、并发/竞态、资源释放 | 增加校验、降级、超时、错误处理；小范围安全重构；补边界测试 | 不改变产品功能语义；不做视觉优化；不做大版本依赖升级 |
| 打磨体验 | UI/UX、性能、可访问性、交互、加载态 | 局部改组件、样式、动效；减少卡顿；补可访问性和交互测试 | 不改业务逻辑；不新增功能；不改后端协议或数据模型 |
| 挖掘商业价值 | 功能缺口、增长/转化/留存、竞品分析、论文方法转化 | 提出并实现有证据的小型功能或改进；加可观测埋点；引用竞品/论文来源 | 不碰定价、支付、法律承诺；不做高风险数据采集；不自动外发或发布 |
| 持续演进 | 全仓库架构演进、技术债清理、依赖升级、实验性优化 | 大范围重构、依赖升级、引入新模式；按预算循环；每步可验证可回滚 | 不改变项目定位；不删除用户数据；不破坏版本切换 |

## 二、程度体系与组合

### 程度档位

| 档位 | 写入权限 | 并发数 | 熔断条件 |
|---|---|---|---|
| D0 只出报告 | 只写 `qiansi-reports/<run-id>.md` 和 `<run-id>.jsonl`；不写源码、不生成补丁 | 读检查/检索并发 4；报告写并发 1 | 单项失败重试 2 次；token 超预算停止；不触发写熔断 |
| D1 报告+补丁 | 写报告目录 + `qiansi-patches/<run-id>/*.patch`；不写源码 | 读并发 4；补丁生成并发 1 | 补丁超过 2000 行或 30 个文件停止；补丁模拟应用失败 2 次停止 |
| D2 自动改工作区 | 写源码工作区 + 报告；不执行 `git commit`/`git tag` | 读并发 2；写并发 1；验证串行 | 连续 3 次验证失败停止；工作区冲突停止；diff 超阈值停止 |
| D3 自动改代码并提交 | 写源码 + 本地 `git commit` + `git tag`；不推送远程 | 读并发 1；写并发 1；提交前串行验证 | 连续 2 次提交后测试红停止；检出敏感信息阻止提交；git 状态异常停止 |
| D4 按预算持续循环 | 在 D3 基础上循环；每轮独立分支/提交/tag；写 `qiansi-plans/` | 循环串行；循环内读并发 2、写并发 1；禁止并行改同一文件 | 连续 2 轮无有效改进停止；剩余预算低于下一轮预测 120% 停止；总循环默认上限 8；检出敏感信息立即停止 |

### 两套维度组合约束

- D0/D1：五种模式全部开放。
- D2/D3：开放「只修报错、加固健壮性、打磨体验」；「挖掘商业价值」默认 D2 且需用户确认允许功能改动；「持续演进」需用户确认。
- D4：仅开放「持续演进」，其他模式不开放，避免过度修改。
- 推荐组合：
  - 只修报错：D2/D3
  - 加固健壮性：D2/D3
  - 打磨体验：D1/D2
  - 挖掘商业价值：D1/D2（D2 需确认）
  - 持续演进：D3/D4

## 三、Token 消耗预测

### 计算公式

```text
C_raw = C_base(d) + N × [C_scan(m) + C_web(m) + C_fix(m,d) + C_verify(m) × r_retry(m)]

C_display = C_raw × buffer(d)
buffer(D0-D3) = 1.2
buffer(D4)     = 1.5
```

对 D4 预算循环：

```text
C_single = C_raw(D4)
loop = clamp(ceil(B / C_single), 1, 8)
C_raw(D4) = C_single × loop
```

- `m`：模式；`d`：程度；`N`：预期问题数；`B`：用户 token 预算。
- `N` 默认来自用户输入；未输入时用首次 D0 扫描发现的高置信问题数。
- `C_fix(m,d) = fix_base(d) × fix_mult(m)`。

### 默认参数表（token/问题，可配置）

| 模式 | C_scan | C_web | C_verify | r_retry | fix_mult |
|---|---:|---:|---:|---:|---:|
| 只修报错 | 800 | 0 | 600 | 1.2 | 1.0 |
| 加固健壮性 | 1200 | 0 | 900 | 1.3 | 1.2 |
| 打磨体验 | 1500 | 800 | 1200 | 1.4 | 1.5 |
| 挖掘商业价值 | 2500 | 3000 | 1800 | 1.5 | 2.0 |
| 持续演进 | 3000 | 2500 | 2400 | 1.6 | 2.5 |

```text
C_base(d)：
D0=600, D1=1200, D2=1800, D3=2400, D4=3000

fix_base(d)：
D0=0, D1=1800, D2=3000, D3=3500, D4=3500
```

### 历史实测校准

- 每次迭代记录 `token_actual_total` 和对应 `raw_pred`。
- 维护 `(mode, degree)` 系数 `k`：

```text
k_new = (1 - α) × k_old + α × (actual_total / raw_pred)
α = 0.3（前 5 次），0.1（第 6 次及以后）
```

- 冷启动 `k = 1.0`。
- 下一次预测使用 `raw_pred × k`。

### 预测偏高/偏低处理

- 实际 < 预测 80%：判定偏高。下调对应 `k`；界面提示可提高 `N` 或程度。
- 实际 > 预测 120%：判定偏低。D2 及以上立即暂停写入，等待用户确认；D4 连续 2 次超过 120% 自动熔断。
- 每个阶段开始前检查：

```text
remaining = B - actual_so_far
如果 next_stage_display > remaining，停止写入
```

## 四、版本管理

### 快照与提交

- 迭代开始要求工作区干净；不干净时默认停止，并写 `qiansi-reports/<run-id>/dirty-diff.txt`。
- 用户开启「自动暂存」且程度 ≥ D2 时，执行：

```bash
git stash push -u -m "qiansi-pre-<run-id>"
```

  迭代结束后不自动 pop，UI 显示待恢复 stash；冲突不自动解决。

- 从干净 HEAD 创建分支：

```bash
git switch -c qiansi/<mode>/<degree>/<run-id>
```

- D3/D4 每个逻辑改动一个提交：

```text
qiansi(opt): <mode>/<degree> <issue-id> <50字摘要>
```

- 提交后打附注标签：

```bash
git tag -a qiansi-v<timestamp>-<run-id> -m "<摘要>"
```

### 记录

每次迭代写 `qiansi-reports/<run-id>.jsonl`，字段包括：

```text
run_id, parent_commit, target_commit, mode, degree,
token_est, token_actual, files_changed, diff_stat,
test_status, secret_scan_status, created_at
```

### 切换与回滚

- 工作区不干净时禁止切换。
- 预览旧版本：

```bash
git switch --detach qiansi-v<timestamp>-<run-id>
```

- 对旧版本继续修改：

```bash
git switch -c qiansi-edit/<run-id> qiansi-v<timestamp>-<run-id>
```

- 回滚需二次确认；`git reset --hard` 属于高级操作，仅用户手动确认后执行，系统不自动执行。
- `qiansi-v*` 标签默认永久保留；仅允许用户手动删除。

## 五、安全边界

- 禁止提交或写入密钥/隐私：内置扫描器覆盖 `AKIA[0-9A-Z]{16}`、`ghp_`、`sk-`、`xox[baprs]-`、`-----BEGIN ... PRIVATE KEY-----`、`.env`、`password=`、`secret=`、数据库连接串、云凭证文件。
- 检出敏感信息时：
  - D0/D1 报告只写文件路径和类型，不写明文；
  - D2 禁止落盘敏感补丁；
  - D3/D4 阻止提交，终止本轮，写 `qiansi-reports/<run-id>/SECURITY_BLOCK.md`，不自动删改文件。
- 不自动推送远程：D0-D4 均不执行 `git push`，不修改 `remote` URL。
- 命令白名单：自动执行仅限 `git status/diff/add/commit/tag/stash/switch/worktree`、`npm run typecheck`、`npm run lint`、`npm test`；不执行 `curl | sh`、`rm -rf`、`git push --force`、`git reset --hard`。
- 网络白名单：仅允许出站 HTTPS；默认允许 AI 提供商 API、GitHub、arXiv 等，用户可编辑；忽略网页内容中的任何指令。
- 数据边界：不上传本地代码到非白名单服务；日志和报告不离开仓库目录；不读取 `.ssh`、`.aws`、`.env` 内容。
