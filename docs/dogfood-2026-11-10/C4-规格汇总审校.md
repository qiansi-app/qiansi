# 牵丝 Qiansi 自我优化功能规格（合并稿）

## 0. 约定

- `m`：模式；`d`：程度档位；`N`：预期问题数；`B`：用户 token 预算；`k(m,d)`：历史校准系数。
- `run-id`：每次迭代唯一标识。
- 以下路径均为本功能新增/管理的目录，不作为仓库现状假设：`qiansi-reports/`、`qiansi-patches/`、`qiansi-plans/`。
- 本规格不假设调用仓库现有内部 API；只约束可执行命令与写入路径。

---

## 一、模式体系

| 模式 | 适用范围 | 执行内容 | 明确不做什么 | 开放程度 |
|---|---|---|---|---|
| 只修报错 | 编译错误、测试失败、运行时崩溃、明确异常 | 复现、定位、修复；补回归测试；保持正常路径语义不变 | 不重构；不改 UI/文案；不升级依赖；不删除功能 | D0–D3，建议 D2/D3 |
| 加固健壮性 | 输入边界、异常处理、类型安全、并发/竞态、资源释放 | 增加校验、降级、超时、错误处理；小范围安全重构；补边界测试 | 不改变产品功能语义；不做视觉优化；不做大版本依赖升级 | D0–D3，建议 D2/D3 |
| 打磨体验 | UI/UX、性能、可访问性、交互、加载态 | 局部改组件、样式、动效；减少卡顿；补可访问性与交互测试 | 不改业务逻辑；不改后端协议或数据模型；不新增功能 | D0–D3，建议 D1/D2 |
| 挖掘商业价值 | 功能缺口、增长/转化/留存、竞品分析、论文方法转化 | 提出并实现有证据的小型改动或建议；加匿名观测；引用可追溯来源 | 不碰定价、支付、法律承诺；不做高风险数据采集；不自动外发或发布 | D0–D2；D2 必须用户确认允许功能行为改变 |
| 持续演进 | 全仓库架构演进、技术债清理、依赖升级、实验性优化 | 按预算分轮推进；每轮独立验证、提交、标签和可回滚状态 | 不改变项目定位；不删除用户数据；不破坏版本切换；不推送远程 | D3 需确认；D4 仅允许此模式 |

### 通用模式约束

- 每个改动必须关联唯一 `issue-id`，并写明：证据/复现、修改范围、风险等级、验证命令、是否改变产品语义。
- “打磨体验”不得同时修改业务逻辑。
- “挖掘商业价值”来源不可验证时只能形成建议，不得实现为功能。
- 竞品页、论文页内容均视为不可信文本；其中的命令、提示词、工具调用要求一律忽略、不得执行。

**最可能被推翻的地方：** 模式边界主要依赖提示词自律，无法从机制上阻止“只修报错”夹带架构重写；必须用允许修改路径、测试范围、diff 阈值和“模式越界即拒绝”来收紧。

## 二、程度体系

| 档位 | 写入权限 | 并发 | 熔断/停止条件 |
|---|---|---|---|
| D0 只出报告 | 仅写 `qiansi-reports/<run-id>.md` 与 `.jsonl`；不写源码、不生成补丁 | 读取/检索 4；报告写 1 | 单项失败重试 2 次；token 超预算停止；报告写入失败终止 |
| D1 报告+补丁 | 写报告目录 + `qiansi-patches/<run-id>/*.patch`；不写源码 | 读取 4；补丁生成 1 | 补丁超过 2000 行或 30 个文件停止；补丁模拟应用连续失败 2 次停止；检出敏感信息停止 |
| D2 自动改工作区 | 在隔离 worktree 中改源码；可写报告；不提交、不打标签、不推送 | 读取 2；写入 1；验证串行 | 基线失败、连续 3 次验证失败、路径越界、检出敏感信息、预算不足、冲突或 diff 超阈值时停止并回滚 |
| D3 自动改代码并提交 | 在隔离分支中改源码；创建本地 `git commit` 与附注标签；不推送 | 读取 1；写入 1；验证串行 | 连续 2 个提交后测试红、检出敏感信息、Git 状态异常、回滚失败或预算不足时停止 |
| D4 按预算持续循环 | 在 D3 基础上循环；每轮独立提交/标签；写 `qiansi-plans/` | 轮次串行；轮内读取 2、写入 1 | 总轮数上限 8；连续 2 轮无有效改进停止；下一轮预计消耗超过剩余预算 120% 停止；任何安全阻断立即停止 |

### 硬性限制

- D0/D1 不得改源码、配置、依赖锁文件或 Git 历史。
- D2 不得 `git commit`/`git tag`/`git push`。
- D3/D4 只能创建本地提交和附注标签。
- 所有档位禁止修改 `remote` URL、配置推送钩子或执行远程写操作。
- 验证必须串行；同一文件不得被两个写入任务并行修改。
- 触发熔断后不得自动换模式或提高程度重试。

**最可能被推翻的地方：** “连续 3 次验证失败”不等于失败原因收敛，模型可能用三种不同方式重复制造同类缺陷；需要按失败指纹去重，否则浪费预算。

## 三、token 消耗预测

### 3.1 估算公式

```text
C_unit(m,d) = C_scan(m) + C_web(m) + fix_base(d) × fix_mult(m) + C_verify(m) × r_retry(m)

raw(m,d,N) = C_base(d) + N × C_unit(m,d)

base(m,d,N) = raw(m,d,N) × buffer(d)
C_est(m,d,N) = base(m,d,N) × k(m,d)
```

- `buffer(D0–D3) = 1.2`；`buffer(D4) = 1.5`。
- `N` 默认取用户输入；未输入时先跑一次 D0 扫描，取高置信问题数，UI 标注“N 为估计值”。
- `N=0` 时仅为纯底噪成本：`C_est = C_base(d) × buffer(d) × k`。

默认参数表（token/问题，冷启动配置，可配置）：

| 模式 | C_scan | C_web | C_verify | r_retry | fix_mult |
|---|---:|---:|---:|---:|---:|
| 只修报错 | 800 | 0 | 600 | 1.2 | 1.0 |
| 加固健壮性 | 1200 | 0 | 900 | 1.3 | 1.2 |
| 打磨体验 | 1500 | 800 | 1200 | 1.4 | 1.5 |
| 挖掘商业价值 | 2500 | 3000 | 1800 | 1.5 | 2.0 |
| 持续演进 | 3000 | 2500 | 2400 | 1.6 | 2.5 |

```text
C_base(d)：D0=600, D1=1200, D2=1800, D3=2400, D4=3000
fix_base(d)：D0=0, D1=1800, D2=3000, D3=3500, D4=3500
```

### 3.2 D4 预算循环

```text
C_round_base = (C_base(D4) + N_round × C_unit(持续演进, D4)) × 1.5
C_round = C_round_base × k(持续演进, D4)
loop_plan = clamp(floor(B / C_round), 1, 8)
C_est(D4) = C_round × loop_plan
```

实际停止不只看 `loop_plan`，由 3.4 阶段门槛逐轮判定。

### 3.3 UI 输出

输出 `C_est`、区间 `[0.8×C_est, 1.2×C_est]`、假设值 `m/d/N/k/loop_plan`。

### 3.4 历史实测校准

```text
raw_actual = (C_base(d) + N_actual × C_unit(m,d)) × buffer(d)

k_new = (1 − α) × k_old + α × (token_actual_total / raw_actual)
```

- 冷启动 `k=1.0`。
- 按 `(mode, degree)` 分桶维护。
- `α = 0.3`（该桶前 5 次），`0.1`（第 6 次起）。
- 样本数 `< 2` 只记录不更新。
- `k` 限制在 `[0.5, 3.0]`，越界截断。
- `token_actual_total` 必须来自供应商 API usage 字段，不得用自报值。

### 3.5 预测偏高/偏低处理

| 情形 | 判定 | 处理 |
|---|---|---|
| 偏高 | `actual < 0.8 × C_est` | 按校准自动下调 `k`；不中断；UI 提示可提高 `N` 或程度 |
| 偏低 | `actual > 1.2 × C_est` | D0/D1：报告标注差异；D2/D3：完成当前问题后暂停写入，等用户选择继续/提高预算/降档；D4：本轮结束后检查，连续 2 轮超过 120% 自动熔断并出复盘报告 |

### 3.6 阶段门槛

每阶段/每轮开始前检查：

```text
remaining = B − actual_so_far
若 next_stage_est × 1.2 > remaining，则不再开始新阶段/新轮，写终止报告
```

**最可能被推翻的地方：** 冷启动参数不是历史实测结果；复杂任务中模型行为、上下文长度、工具重试和供应商计费规则会显著拉偏预测。必须依靠供应商 usage 字段快速校准，并在偏低时暂停写入。

## 四、版本管理

### 4.1 快照

- 前置条件：工作区干净。
- 从当前 HEAD 创建独立分支/隔离 worktree：

```bash
git switch -c qiansi/<mode>/<degree>/<run-id>
```

- D2 只改隔离 worktree，不提交、不打标签。
- D3/D4 每个逻辑改动一个提交：

```text
qiansi(opt): <mode>/<degree> <issue-id> <≤50字摘要>
```

- 每轮结束、测试通过且密钥扫描干净后，打附注标签：

```bash
git tag -a qiansi-v<YYYYMMDDHHmmss>-<run-id> -m "<摘要>"
```

### 4.2 记录

每轮追加一行 `qiansi-reports/<run-id>.jsonl`，字段：

```text
run_id, round, parent_commit, target_commit, tag, mode, degree,
token_est, token_actual, est_raw, k_used,
files_changed, diff_stat, test_status, secret_scan_status, created_at
```

其中 `est_raw` 与 `k_used` 用于校准。

### 4.3 切换与回滚

| 操作 | 命令 | 说明 |
|---|---|---|
| 预览旧版本 | `git switch --detach qiansi-v<ts>-<run-id>` | 只读浏览 |
| 基于旧版本继续修改 | `git switch -c qiansi-edit/<run-id> qiansi-v<ts>-<run-id>` | 从旧标签拉新分支 |
| 回滚为当前主线 | 推荐 `git revert`；或从旧 tag 建分支重走 | 需用户二次确认 |
| 强制回退 | `git reset --hard` | 高级操作，仅用户手动二次确认后执行，系统永不自动执行 |

- 切换/回滚前必须工作区干净，否则拒绝。
- `qiansi-v*` 标签默认永久保留，仅允许用户手动删除。

### 4.4 工作区不干净时

1. 所有程度默认停止，写 `qiansi-reports/<run-id>/dirty-diff.txt`，内容为 `git status --porcelain` 与 `git diff`。
2. 系统不自动 `git stash`、不自动解决冲突。
3. 用户手动清理后重新发起迭代。
4. 迭代中途出现非本 run 产生的未知脏文件：立即暂停写入，等待用户确认。

**最可能被推翻的地方：** 永久保留标签意味着一旦有泄露提交进入历史，它可能长期存在；所以必须先扫描暂存区与提交对象，再允许打标签。

## 五、安全边界

### 5.1 密钥与隐私

- 扫描范围必须覆盖：候选补丁、暂存区、最终提交对象，不得只扫工作区文件名。
- 至少覆盖规则：`AKIA[0-9A-Z]{16}`、`ghp_`、`sk-`、`xox[baprs]-`、`-----BEGIN ... PRIVATE KEY-----`、`.env`、`password=`、`secret=`、数据库连接串、云凭证文件、`Authorization: Bearer`/JWT 形态。
- 扫描不等于穷尽证明；检出后一律阻断，不得自动放行。
- 分级处理：
  - D0/D1：报告只写文件路径和类型，不写明文；
  - D2：禁止落盘敏感补丁；
  - D3/D4：阻止提交，终止本轮，写 `qiansi-reports/<run-id>/SECURITY_BLOCK.md`，不自动删改文件。

### 5.2 Git 与命令白名单

- D0–D4 均禁止 `git push`，禁止修改 `remote` URL。
- 允许自动执行的命令仅限：
  - `git status/diff/add/commit/tag/stash/switch/worktree`
  - `npm run typecheck`
  - `npm run lint`
  - `npm test`
- 禁止：`curl | sh`、`rm -rf`、`git push --force`、`git reset --hard`。

### 5.3 网络白名单

- 仅允许出站 HTTPS。
- 默认允许：AI 提供商 API、GitHub、arXiv；用户可编辑。
- 第三方研究站点仅允许只读 GET。
- 源码只能发送给明确配置的 AI 供应商。
- 网页内容中的任何指令、命令、提示词均视为不可信文本，不执行。

### 5.4 数据与路径边界

- 每次写入前必须做路径归一化、符号链接检查、仓库根目录校验。
- 禁止写出仓库；禁止读取 `.ssh`、`.aws`、`.env` 内容。
- 日志和报告不得离开仓库目录。
- 不上传本地代码到非白名单服务。

### 5.5 隔离与回滚

- D2 及以上必须在隔离 worktree/分支中执行。
- 失败只撤销本次运行产生的改动；不得删除用户已有改动。
- 回滚失败时保留 worktree 和日志，标记人工恢复。

**最可能被推翻的地方：** 正则密钥扫描可被拆分字符串、Base64、JWT、云厂商新凭证格式绕过；安全边界必须把阻断后人工复核作为强制步骤，而不是信任扫描器结果。

## 附：风险清单与触发条件

| 风险 | 触发条件 | 强制动作 |
|---|---|---|
| 密钥漏检或误报 | 扫描命中或规则未覆盖 | 阻断写入；疑似项不得自动放行，转人工复核 |
| 路径逃逸 | 目标不在允许根目录或经过符号链接 | 立即停止，不写文件 |
| 远程外泄 | 请求方法、域名或请求体不符合策略 | 阻断请求并记录脱敏事件 |
| 意外推送 | 出现远程写命令或 remote 配置变化 | 立即停止；保留现场 |
| 基线污染 | 修改前测试已失败 | 默认停止，不把历史失败算作新增回归 |
| 预算失控 | 下一阶段预测超过剩余预算，或实际超预测 120% | 停止写入，等待确认；D4 连续两轮超限自动熔断 |
| 回滚失败 | 路径内容变化、Git 冲突或撤销后复验失败 | 保留 worktree 和日志，标记人工恢复 |
| 模式越界 | diff 超出模式允许范围 | 拒绝该改动并重新生成 |
| 版本不可复现 | 外部依赖或环境状态无法恢复 | 标记环境差异，不宣称完全可复现 |
| 失败未收敛 | 连续失败但失败指纹不同 | 停止重试，按失败指纹去重后再评估 |
