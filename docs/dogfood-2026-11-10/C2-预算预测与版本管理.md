## 三、Token 消耗预测

### 3.1 估算公式

输入：模式 `m`、程度 `d`、预算 `B`（token）、预期问题数 `N`。

```text
单问题成本  C_unit(m,d) = C_scan(m) + C_web(m) + fix_base(d) × fix_mult(m) + C_verify(m) × r_retry(m)
基准预测    C_raw = C_base(d) + N × C_unit(m,d)
对外预测    C_est = C_raw × k(m,d) × buffer(d)

buffer：D0–D3 = 1.2；D4 = 1.5
k(m,d)：历史校准系数，冷启动 1.0（见 3.3）
```

默认参数表（token/问题，可配置）：

| 模式 m | C_scan | C_web | C_verify | r_retry | fix_mult |
|---|---:|---:|---:|---:|---:|
| 只修报错 | 800 | 0 | 600 | 1.2 | 1.0 |
| 加固健壮性 | 1200 | 0 | 900 | 1.3 | 1.2 |
| 打磨体验 | 1500 | 800 | 1200 | 1.4 | 1.5 |
| 挖掘商业价值 | 2500 | 3000 | 1800 | 1.5 | 2.0 |
| 持续演进 | 3000 | 2500 | 2400 | 1.6 | 2.5 |

```text
C_base(d)：D0=600, D1=1200, D2=1800, D3=2400, D4=3000
fix_base(d)：D0=0, D1=1800, D2=3000, D3=3500, D4=3500
```

- `N` 默认取用户输入；未输入时先跑一次 D0 扫描，取高置信问题数，UI 标注「N 为估计值」。
- `N=0` 时 `C_est = C_base(d) × k × buffer`（纯底噪成本）。

**D4 预算循环**（每轮结构相同，`N` 为每轮预期问题数）：

```text
C_round = (C_base(D4) + N × C_unit(持续演进, D4)) × k × 1.5
loop_plan = clamp(floor(B / C_round), 1, 8)
C_est(D4) = C_round × loop_plan
```

实际停止不受 loop_plan 硬约束，由 3.4 的阶段门槛逐轮判定。

**UI 输出**：`C_est`、区间 `[0.8×C_est, 1.2×C_est]`、所用假设（m/d/N/k/loop_plan）。示例：

- 只修报错 × D3，N=10：C_unit = 800+0+3500+720 = 5020；C_est = (2400+10×5020)×1.2 = **63,120**，区间约 5.0万–7.6万。
- 持续演进 × D4，每轮 N=5，B=2,000,000，k=1.0：C_round = (3000+5×18090)×1.5 = 140,175；loop_plan = floor(14.27)=14 → 截为 8；C_est = **1,121,400**。

### 3.2 历史实测校准

每次迭代结束后，按 `(mode, degree)` 分桶维护系数 `k`：

```text
raw_pred = (C_base(d) + N_actual × C_unit(m,d)) × buffer(d)   // 不含 k 的基准
k_new = (1−α) × k_old + α × (token_actual_total / raw_pred)
α = 0.3（该桶前 5 次），0.1（第 6 次起）
```

- 冷启动 k=1.0；样本数 <2 时只记录不更新。
- k 限制在 `[0.5, 3.0]`，越界截断，防止单次异常拉偏。
- 下一次预测直接用 `C_raw × k × buffer`；k 值随 UI 预测一并展示。

### 3.3 预测偏高/偏低处理

| 情形 | 判定 | 处理 |
|---|---|---|
| 偏高 | actual < 0.8 × C_est | EMA 自动下调 k；不中断；UI 提示「可提高 N 或程度以用满预算」 |
| 偏低 | actual > 1.2 × C_est | D0/D1：报告标注差异；D2/D3：完成当前问题后暂停写入，展示差异，等用户选择（继续 / 提高预算 / 降档）；D4：本轮结束后检查，**连续 2 轮 >120% 自动熔断**并出复盘报告 |

**阶段门槛（每阶段/每轮开始前检查）**：

```text
remaining = B − actual_so_far
若 next_stage_est × 1.2 > remaining → 不再开始新阶段/新轮，写终止报告
```

## 四、版本管理

### 4.1 快照（提交与标签）

- 迭代开始前置条件：工作区干净（见 4.4）。
- 从当前 HEAD 建独立分支：

```bash
git switch -c qiansi/<mode>/<degree>/<run-id>
```

- D3/D4 每个逻辑改动一个提交（D2 只改工作区不提交）：

```text
qiansi(opt): <mode>/<degree> <issue-id> <≤50字摘要>
```

- 每轮迭代结束、测试通过且密钥扫描干净后，打附注标签（时间戳用 `YYYYMMDDHHmmss`，保证字典序=时间序）：

```bash
git tag -a qiansi-v<YYYYMMDDHHmmss>-<run-id> -m "<摘要>"
```

- 仅使用白名单命令：`git status/diff/add/commit/tag/stash/switch/worktree`；不执行 `git push`、`git reset --hard`。

### 4.2 记录

每轮追加一行 `qiansi-reports/<run-id>.jsonl`：

```text
run_id, round, parent_commit, target_commit, tag, mode, degree,
token_est, token_actual, est_raw, k_used,
files_changed, diff_stat, test_status, secret_scan_status, created_at
```

其中 `est_raw`（不含 k 的基准预测）与 `k_used` 供 3.2 校准复用。

### 4.3 切换与回滚

| 操作 | 命令 | 说明 |
|---|---|---|
| 预览旧版本 | `git switch --detach qiansi-v<ts>-<run-id>` | 只读浏览，不产生提交 |
| 基于旧版本继续修改 | `git switch -c qiansi-edit/<run-id> qiansi-v<ts>-<run-id>` | 从旧标签拉新分支，历史不受影响 |
| 回滚到旧版本为主线 | 推荐 `git revert`（生成反向提交，保留历史）；或从旧 tag 建分支重走 | 需用户二次确认 |
| 强制回退 | `git reset --hard` | 高级操作，仅用户手动二次确认后执行，系统永不自动执行 |

- 切换/回滚前必须工作区干净，否则直接拒绝。
- `qiansi-v*` 标签默认永久保留，仅允许用户手动删除。

### 4.4 工作区不干净的处理

1. **默认（所有程度）**：停止迭代，写 `qiansi-reports/<run-id>/dirty-diff.txt`（`git status --porcelain` + `git diff` 输出），UI 提示用户先提交或暂存。
2. **自动暂存（用户显式开启且程度 ≥ D2）**：

```bash
git stash push -u -m "qiansi-pre-<run-id>"
```

   迭代结束后**不自动 pop**；UI 显示「待恢复 stash: qiansi-pre-\<run-id\>」；恢复冲突不自动解决，交用户手动处理。

3. **迭代中途出现脏文件**：本 run 自己写入的改动走正常提交流程纳入快照；出现非本 run 的未知脏文件 → 立即暂停写入，等待用户确认。
4. **切换/回滚时脏**：一律拒绝并提示，不做任何自动 stash。
