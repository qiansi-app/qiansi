# 「牵丝 Qiansi」自我优化功能规格

## 方案主张复述

牵丝通过五种优化模式、五个自动化程度档位，在仓库内扫描问题、按需联网调研、生成并验证改动，并使用 Git 提交和标签保留版本。系统以 token 预算控制持续迭代，同时通过密钥扫描、仓库边界、网络白名单和失败回滚机制限制风险。

## 最强的反对论证

1. **模式名称不能证明行为边界正确。**  
   “只修报错”可能顺手重写依赖，“打磨体验”可能改变业务语义，“挖掘商业价值”则可能把未经证实的竞品做法直接变成功能。  
   **具体失败场景：** UI 按钮颜色调整同时改变了提交参数，测试只覆盖成功路径，用户数据被写入错误字段，但最终提交描述仍写着“修复按钮样式”。

2. **token 预测在首次运行和复杂任务中不可靠。**  
   问题数 `N` 通常在扫描前未知，而模型行为、上下文长度、工具重试和供应商计费规则都会显著影响消耗。  
   **具体失败场景：** 首次扫描发现 2 个问题，但实际修复需要读取 30 个文件并重跑 5 次测试，预测消耗 20k，实际消耗 60k，D4 已经超过用户预算。

3. **正则密钥扫描不足以证明“禁止提交密钥”。**  
   `password=`、固定前缀等规则会漏掉自定义格式、拆分字符串、Base64、JWT、云厂商新凭证，也容易把测试夹具误报为真密钥。  
   **具体失败场景：** 改动中包含 `Authorization: Bearer eyJ...`，扫描器未命中，随后该改动被提交并打上可长期保留的版本标签。

4. **“仓库内运行”不等于“不会越界”。**  
   子进程、符号链接、绝对路径参数、Git hooks、测试脚本都可能访问仓库外文件；仅检查当前工作目录无法阻止这些行为。  
   **具体失败场景：** 测试脚本读取 `~/.aws/credentials`，或者报告中的路径包含 `../../home/user/private-key`，最终被写入日志。

5. **失败回滚与“不自动 destructive Git 操作”存在冲突。**  
   `git reset --hard` 能快速回滚，但可能破坏用户在运行期间产生的改动；只生成反向补丁又不能保证所有失败场景都能恢复。  
   **具体失败场景：** D3 提交后测试失败，系统执行 `reset --hard`，同时删除了用户在迭代期间手动保存但尚未提交的文件。

6. **GitHub 在网络白名单中仍可能成为数据外泄通道。**  
   允许访问 GitHub、arXiv 不等于允许上传源码、Issue 内容或带凭证的 URL。  
   **具体失败场景：** 调研请求的 URL 查询参数包含源码片段或 token，日志和代理记录将其持久化到第三方服务。

## 主张成立条件

上述方案只有在以下条件下才可安全实施：

- 所有写文件、执行命令、联网、暂存、提交、标签和回滚操作都经过统一能力网关，而不是由模型直接调用 shell。
- 每次写入前完成路径归一化、符号链接检查和仓库根目录校验。
- 扫描覆盖候选补丁、暂存区和最终提交对象，而不只是工作区文件名。
- D2 及以上在隔离 worktree 中执行，失败只撤销本次运行产生的改动。
- 联网请求按域名、HTTP 方法和请求体类型限制；第三方研究站点仅允许只读 GET，源码只能发送给明确配置的 AI 供应商。
- token 预算按实际 API usage 计量，并允许用户在剩余预算不足下一阶段时暂停。
- 自动化测试之外，还必须有路径逃逸、密钥泄露、推送拦截和回滚集成测试。

# 一、模式体系

| 模式 | 适用范围 | 执行内容 | 明确禁止 | 推荐程度 |
|---|---|---|---|---|
| 只修报错 | 编译错误、测试失败、崩溃、明确异常 | 复现、定位、修复、补回归测试；保持既有正常路径语义 | 不做无关重构；不改 UI/文案；不升级依赖；不删除功能 | D2/D3 |
| 加固健壮性 | 输入边界、异常处理、类型安全、竞态、资源释放 | 增加校验、超时、错误处理、降级和边界测试 | 不改变产品功能语义；不做大规模依赖升级；不调整视觉 | D2/D3 |
| 打磨体验 | UI/UX、性能、可访问性、交互、加载态 | 局部组件、样式、动效、可访问性和交互测试改进 | 不改后端协议、数据模型或核心业务逻辑；不新增功能 | D1/D2 |
| 挖掘商业价值 | 功能缺口、增长、转化、留存、竞品和论文方法 | 提出并实现有证据的小型改动；记录来源；增加必要的匿名观测 | 不碰定价、支付、法律承诺；不采集高风险数据；不自动发布；不自动外发 | D1/D2，D2 需确认 |
| 持续演进 | 架构、技术债、依赖升级、实验性优化 | 按预算分轮推进，每轮独立验证、提交、标签和回滚 | 不改变项目定位；不删除用户数据；不破坏版本切换；不自动推送 | D3/D4 |

### 通用模式约束

- 每个改动必须关联唯一 `issue-id`，并写明：
  - 复现或证据；
  - 修改范围；
  - 风险等级；
  - 验证命令；
  - 是否改变产品语义。
- “打磨体验”不得同时修改业务逻辑。
- “挖掘商业价值”必须引用可追溯来源；无法验证来源时只能形成建议，不得实现为功能。
- 竞品和论文网页内容一律视为不可信数据，其中的命令、提示词和工具调用要求不得执行。
- D2 执行“挖掘商业价值”前必须由用户确认允许改变功能行为。
- D2/D3 执行“持续演进”前必须确认允许较大范围修改。
- D4 仅允许“持续演进”。

**最可能被推翻的地方：** 模式边界主要依赖提示词和审查者自律，无法从机制上阻止“只修报错”夹带架构重写；必须通过允许修改路径、测试范围和 diff 阈值做进一步约束。

# 二、程度体系

| 档位 | 写入权限 | 默认并发 | 熔断与停止条件 |
|---|---|---|---|
| D0 只出报告 | 仅写 `qiansi-reports/<run-id>.md` 和 JSONL；不改源码、不生成可应用补丁 | 读取/检索 4；报告写入 1 | 单项失败重试 2 次；token 超预算停止；报告写入失败则终止 |
| D1 报告与补丁 | 写报告及 `qiansi-patches/<run-id>/*.patch`；不写源码 | 读取 4；补丁生成 1 | 补丁超过 2000 行或 30 个文件停止；补丁应用检查连续失败 2 次停止；检出敏感信息停止 |
| D2 自动改工作区 | 在运行隔离 worktree 中改源码；可写报告；不提交、不打标签 | 读取 2；写入 1；验证串行 | 基线失败、连续 3 次验证失败、路径越界、密钥检出、预算不足、冲突或 diff 超阈值时停止并回滚 |
| D3 自动改代码并提交 | 在隔离分支中改源码、创建本地提交和标签；不推送 | 读取 1；写入 1；验证串行 | 连续 2 个提交后测试失败、检出敏感信息、Git 状态异常、回滚失败或预算不足时停止 |
| D4 按预算循环 | D3 能力加多轮计划；每轮独立提交和标签 | 轮次串行；轮内读取 2、写入 1 | 总轮数最多 8；连续 2 轮无有效改进停止；下一轮预计消耗高于剩余预算 120% 停止；任何安全阻断立即停止 |

### 硬性限制

- D0/D1 不允许修改源码、配置、依赖锁文件或 Git 历史。
- D2 不允许 `git commit`、`git tag`、`git push`。
- D3/D4 只能创建本地提交和附注标签。
- 所有档位均禁止修改 `remote` URL、配置推送钩子或执行远程写操作。
- 验证必须串行执行，避免多个测试进程争用端口、数据库或临时目录。
- 同一文件不得被两个写入任务并行修改。
- 达到任何熔断条件后，不得自动换模式或提高程度重试。

**最可能被推翻的地方：** “连续 3 次验证失败”不等于失败原因已经收敛，模型可能用三种不同方式重复制造同类缺陷；需要按失败指纹去重，否则会浪费预算。

# 三、token 消耗预测

## 1. 输入

- `m`：模式；
- `d`：程度；
- `N`：预期问题数；
- `B`：用户总 token 预算；
- `S`：已消耗 token；
- `r`：实际重试次数。

## 2. 默认估算参数

以下仅是**冷启动配置值，不应宣称为历史实测结果**。

| 模式 | 扫描 | 调研 | 验证 | 默认重试系数 | 修复系数 |
|---|---:|---:|---:|---:|---:|
| 只修报错 | 800 | 0 | 600 | 1.2 | 1.0 |
| 加固健壮性 | 1200 | 0 | 900 | 1.3 | 1.2 |
| 打磨体验 | 1500 | 800 | 1200 | 1.4 | 1.5 |
| 挖掘商业价值 | 2500 | 3000 | 1800 | 1.5 | 2.0 |
| 持续演进 | 3000 | 2500 | 2400 | 1.6 | 2.5 |

```text
C_base:
D0 = 600
D1 = 1200
D2 = 1800
D3 = 2400
D4 = 3000

fix_base:
D0 = 0
D1 = 1800
D2 = 3000
D3 = 3500
D4 = 3500
```

## 3. 计算公式

```text
C_fix(m, d) = fix_base(d) × fix_mult(m)

C_single =
  C_base(d)
  + N × (
      C_scan(m)
      + C_web(m)
      + C_fix(m, d)
      + C_verify(m) × r_retry(m)
    )

C_display = C_single × buffer(d) × k(m, d)
```

默认缓冲：

```text
buffer(D0-D3) = 1.2
buffer(D4) = 1.5
```

D4 的轮数不得只按总预算直接相乘，应结合已消耗量：

```text
remaining = max(0, B - S)

estimated_round_display = C_single × 1.5 × k(m, D4)

loop = clamp(
  floor(remaining / estimated_round_display),
  0,
  8
)
```

若 `loop = 0`，不启动新一轮。每个阶段开始前重新检查：

```text
next_stage_display > remaining
```

成立时禁止进入该阶段。

## 4. `N` 的确定

1. 用户明确给出时使用用户值。
2. 用户未给出时，先运行一次受限扫描，以高置信问题数作为初始 `N`。
3. 扫描阶段设置独立上限，避免为了得到更准确的 `N` 无限消耗。
4. 后续发现的新问题不得自动突破总预算，只能启用新的用户确认轮次。

## 5. 历史校准

每次运行记录：

```text
token_est
token_actual
raw_pred
mode
degree
```

`token_actual` 必须来自供应商返回的 usage 数据并汇总，不能用字符数直接代替 token。

```text
k_new =
  (1 - α) × k_old
  + α × (token_actual / raw_pred)
```

```text
冷启动 k = 1.0
前 5 次 α = 0.3
第 6 次起 α = 0.1
```

建议同时保留样本数和置信区间；样本不足 5 次时，不应仅凭一次极端值显著调整 `k`。

## 6. 偏高与偏低处理

- `token_actual < 0.8 × raw_pred`：
  - 标记预测偏高；
  - 更新 `k`；
  - 不自动增加问题数；
  - 提示用户可提高 `N` 或程度。
- `token_actual > 1.2 × raw_pred`：
  - 标记预测偏低；
  - D2 及以上暂停后续写入；
  - D4 连续两轮超过 120% 自动熔断；
  - 等待用户确认后才能继续。
- 预测与实际不一致但失败发生在供应商计费异常时，不得把供应商异常直接归因于模式系数，应单独记录。

**最可能被推翻的地方：** `k(m,d)` 很难覆盖不同问题类型、仓库规模和上下文长度；按单一模式和程度校准可能产生系统性偏差，后续应增加仓库规模和问题类别维度。

# 四、版本管理

## 1. 运行前快照

D2/D3/D4 执行前必须记录：

```text
repo_root
base_commit
base_branch
git_status
run_id
```

建议使用仓库内被忽略的隔离目录：

```text
<repo>/.qiansi-worktrees/<run-id>
```

通过 `git worktree add --detach` 创建隔离工作区，再从 `base_commit` 创建：

```text
qiansi/<mode>/<degree>/<run-id>
```

这样可以避免直接覆盖用户当前工作区。

### 工作区不干净

- 检查：

```bash
git status --porcelain=v1 --untracked-files=all
```

- 默认立即停止，只生成诊断报告。
- 不自动 stash 用户改动。
- 如果未来提供“自动暂存”选项，必须：
  - 用户显式开启；
  - 先扫描 stash 内容是否含敏感信息；
  - 使用唯一名称；
  - 结束后不自动 pop；
  - 冲突时停止并保留 stash。
- `qiansi-reports/`、`qiansi-plans/`、`.qiansi-worktrees/` 必须在 `.gitignore` 中，否则“写报告后工作区变脏”会形成自相矛盾。

## 2. 提交和标签

- D2 不提交，只保留 worktree、base SHA 和二进制 diff。
- D3/D4 每个逻辑改动一个提交：

```text
qiansi(opt): <mode>/<degree> <issue-id> <不超过50字摘要>
```

- 提交前必须：
  1. 基线与当前测试对比；
  2. 执行该模式要求的验证；
  3. `git diff --check`；
  4. 密钥扫描暂存区；
  5. 检查 diff 范围。
- 全部验证成功后才创建附注标签：

```text
qiansi-v<timestamp>-<run-id>
```

- D4 每轮成功后创建对应标签。
- 失败提交不创建正式版本标签。

## 3. 运行记录

每次运行写：

```text
qiansi-reports/<run-id>.jsonl
```

至少包含：

```text
run_id
issue_id
parent_commit
target_commit
mode
degree
token_est
token_actual
files_changed
diff_stat
test_commands
test_status
secret_scan_status
path_boundary_status
network_policy_status
rollback_status
created_at
```

报告只写密钥类型和文件路径，不写疑似密钥原文。

## 4. 切换

```bash
git switch --detach qiansi-v<timestamp>-<run-id>
```

基于旧版本继续修改：

```bash
git switch -c qiansi-edit/<run-id> qiansi-v<timestamp>-<run-id>
```

切换前必须确认主工作区干净；存在冲突时停止，不自动解决。

## 5. 回滚与失败恢复

### D2

- 失败时只恢复本轮记录过的修改路径；
- 恢复前检查当前内容是否仍等于本轮生成结果；
- 若用户或其他进程已修改该路径，不覆盖，保留现场并停止；
- 系统不自动执行 `git reset --hard`。

### D3/D4

- 提交后验证失败时，对本轮提交执行：

```bash
git revert --no-edit <commit>
```

- 回滚后重新运行验证。
- D4 某轮失败时，先撤销该轮提交，再停止整个循环。
- 回滚冲突时：
  - 不强推；
  - 不硬重置；
  - 不删除提交；
  - 将分支标记为需人工处理；
  - 保留失败日志和 worktree。

### D0/D1

没有源码写入，不需要源码回滚；删除或保留未完成补丁由报告状态标记决定。

**最可能被推翻的地方：** Git 标签只能保存提交树，不能保证外部依赖、构建产物、环境变量和本地数据库状态可复现；版本可切换不等于运行环境完全可复现。

# 五、安全边界与可执行检查点

## 1. 禁止提交或写入密钥

### 检查点 S1：候选文件生成后、落盘前

检查：

- 私钥头；
- AWS 访问密钥格式；
- GitHub、Slack、OpenAI 风格 token；
- JWT；
- 数据库连接串；
- 云凭证文件；
- `password`、`secret`、`token`、`api_key` 赋值；
- 高熵字符串。

命中时：

- D0/D1：报告仅记录路径、规则名和哈希指纹；
- D2：不得落盘该补丁；
- D3/D4：不得暂存或提交。

### 检查点 S2：`git add` 前

只扫描本轮候选文件，不得把整个仓库中与本次改动无关的历史密钥自动加入暂存区。

### 检查点 S3：`git commit` 前

必须扫描暂存区最终 blob：

```bash
git diff --cached --binary
```

检查对象是暂存区内容，而不是工作区旧内容。

### 检查点 S4：提交后

再次扫描新提交对象：

```bash
git show --format= --binary <commit>
```

命中则：

1. 立即停止；
2. 执行 `git revert`；
3. 回滚后复扫；
4. 写 `SECURITY_BLOCK.md`，其中不包含明文秘密。

### 规则要求

- 规则至少分为“确定密钥”“疑似密钥”“普通测试数据”三级。
- 疑似密钥默认阻断，不得自动放行。
- 固定正则只能作为第一层；高熵检测不能单独证明是密钥，因此高熵项默认需要人工复核或更严格阻断。
- 扫描器必须支持项目自定义规则，例如 `.env.example`、测试夹具和明确的假 token 白名单。

## 2. 禁止越出仓库

### 检查点 P1：仓库根目录解析

```bash
git rev-parse --show-toplevel
```

规范化后保存唯一允许根目录。

### 检查点 P2：每次文件写入前

对目标路径执行：

1. 转换为绝对路径；
2. 消除 `..`；
3. 解析父目录真实路径；
4. 拒绝符号链接指向仓库外；
5. 确认目标位于允许目录：
   - 源码 worktree；
   - `qiansi-reports/`；
   - `qiansi-patches/`；
   - `qiansi-plans/`。

不允许仅使用字符串前缀判断路径是否在仓库内。

### 检查点 P3：命令执行前

统一命令网关必须检查：

- 可执行程序；
- 参数；
- 工作目录；
- 环境变量；
- 输入输出路径。

至少禁止自动执行：

```text
curl | sh
rm -rf
git push
git push --force
git reset --hard
git clean
git remote set-url
```

还需要禁止读取：

```text
~/.ssh
~/.aws
.env
仓库外的绝对路径
```

### 检查点 P4：写入时防竞争

文件写入采用“临时文件 + 原子重命名”，并在打开前再次确认父目录未变成指向仓库外的符号链接。

**失败处理：** 立即停止，保留已产生的仓库内诊断报告，不继续执行后续命令。

## 3. 禁止自动推送

### 检查点 N1：命令网关

任何包含 `push`、`gh pr create`、`gh release create` 等远程写操作的命令直接拒绝。系统自身不得提供“自动推送”参数。

### 检查点 N2：网络出口代理

- AI 供应商 API：仅允许配置中的域名和方法；
- GitHub、arXiv 等调研站点：默认只允许 HTTPS `GET`/`HEAD`；
- 禁止向第三方研究站点提交源码、diff、报告、Issue 内容或请求体；
- URL 中不得包含源码、token 或用户隐私；
- 禁止重定向到非白名单域名；
- 日志只保存域名、方法、状态码和字节数，不保存敏感请求体。

### 检查点 N3：Git 远程配置完整性

运行前后记录并比较：

```bash
git remote -v
git config --get-regexp '^remote\..*\.(url|pushurl)$'
```

发生变化即停止。

### 检查点 N4：凭证约束

- GitHub token 只拥有读取公开资料所需的最小权限；
- 不允许把 GitHub token 传给网页内容；
- 研究站点 Cookie 和认证头不得写入报告；
- 不执行网页返回的脚本或安装命令。

## 4. 失败必须回滚

### 检查点 R0：修改前基线

D2 及以上先执行最小基线验证：

- 基线已经失败时，默认停止；
- 若任务正是修复该错误，必须在报告中标记“基线已知失败”，并保存失败指纹；
- 修改后新增失败与基线失败必须区分。

### 检查点 R1：写入后验证

每次逻辑修改后串行验证。失败时：

- D1：丢弃未应用补丁，仅保留失败报告；
- D2：按修改路径撤销本轮写入；
- D3/D4：撤销对应提交并复验。

### 检查点 R2：回滚后验证

回滚完成后必须重新验证：

- 源码恢复到 `base_commit` 的目标文件状态；
- 测试结果恢复到基线；
- 无新增未提交文件；
- 无残留进程占用端口或临时资源。

### 检查点 R3：回滚失败

若撤销失败：

1. 禁止继续迭代；
2. 禁止提交、打标签或推送；
3. 保留 worktree、提交、日志和失败快照；
4. 在 UI 标记“需人工恢复”；
5. 不执行 `reset --hard` 或其他破坏性操作。

## 验收测试

1. **密钥阻断：** 候选文件、暂存区和提交对象分别注入假密钥，三处均不得产生有效提交。
2. **仓库逃逸：** 使用 `../outside`、绝对路径、符号链接和父目录替换，均不得写出仓库。
3. **推送阻断：** 无论通过模型、任务脚本还是 UI，均无法执行远程写操作。
4. **回滚：** 分别在写入后、暂存后、提交后注入失败，最终源码和测试状态必须恢复到基线。
5. **预算熔断：** 模拟实际消耗超过预测 120%，D2 必须暂停，D4 连续两轮超限必须停止。
6. **脏工作区：** 存在未提交改动时，D2/D3/D4 必须停止且不得自动 stash。
7. **报告污染：** 报告中不得出现疑似密钥原文、认证头、源码请求体或仓库外绝对路径。
8. **模式隔离：** “打磨体验”运行中若修改后端协议或数据模型，必须被阻断。

## 保留风险清单

| 风险 | 触发条件 | 强制动作 |
|---|---|---|
| 密钥漏检或误报 | 扫描命中或规则未覆盖 | 阻断写入；疑似项不得自动放行 |
| 路径逃逸 | 目标不在允许根目录或经过符号链接 | 立即停止，不写文件 |
| 远程外泄 | 请求方法、域名或请求体不符合策略 | 阻断请求并记录脱敏事件 |
| 意外推送 | 出现远程写命令或 remote 配置变化 | 立即停止；保留现场 |
| 基线污染 | 修改前测试已失败 | 默认停止，不把历史失败算作新增回归 |
| 预算失控 | 下一阶段预测超过剩余预算或实际超预测 120% | 停止写入，等待确认 |
| 回滚失败 | 路径内容变化、Git 冲突或撤销后复验失败 | 保留 worktree 和日志，标记人工恢复 |
| 模式越界 | diff 超出模式允许范围 | 拒绝该改动并重新生成 |
| 版本不可复现 | 外部依赖或环境状态无法恢复 | 标记环境差异，不宣称完全可复现 |
