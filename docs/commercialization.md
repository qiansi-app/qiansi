# 牵丝商业化与盈利计划

状态：内部决策稿（2026-11-16）。事实基线是仓库与本机实测；所有市场规模、增长率、客单价、转化率一律标注「待验证」，不引用未经核实的外部数字。

## 摘要

牵丝是一个 MIT 开源、本地优先的多 AI 协作画布。它的商业化不靠卖 token、不靠云托管，而是**把「多模型协作过程」本身作为付费价值**：Pro 年度授权承载自动化与规模化能力，工作流/手册包降低首次成功成本，支持与咨询兜住长尾。单维护者 + 零现金投入的约束下，路线是「先卖后做」：4 周内用预订页验证付费意愿，没有真实留资就不写付费墙代码，退回开源 + 赞助。

## 现状与约束

**现状**：Electron 桌面版 + VS Code 画布扩展 + 本地服务（Hono + SSE）；v0.1.0 公开预览、MIT 开源、单用户本地运行、无云服务、无账号体系。核心差异五点：画布即工作流（模型是节点，连线带 assign/handoff/review/context 语义）、团队名册（一人一职 + 手册广播 + 自治档位与工具白名单）、自省闭环（体检→对标→复盘→互审→执行→校验→快照）、用户视角验收、会话接管（外部 agent 的会话自动变成画布并开跑）。另有 MCP server 与 Claude Code 插件。

**约束**（决定了什么不能做）：

- 人力：一人全职 + 兼职支持，没有销售与客服；
- 技术：不做云后端、不做运维，不承诺 SLA、不做多人实时协作、不做在线托管版；
- 红线：本地优先与「数据不出机器」、MIT 开源承诺、验收闭环与 effort 校准永不砍；
- 预算：现金接近零，主要成本是时间与自测 token；
- 节奏：4 周一个验证周期，每周期必须产出可对外演示的交付物，否则回退。

## 目标客户

从已经在用的人开始卖，不从泛人群开始：

1. **个人专业使用者（首选）**：独立研究者、内容生产者、独立开发者；已为 2 个以上模型付费、正在用 Claude Code / Codex / Cursor 干活；痛点是多模型结果无法对照、返工理由不可追溯、token 花在哪看不见。
2. **小团队技术负责人（3–10 人）**：需要把「怎么让 AI 干活」固化成可交付、可教学、可导出的图，而不是散落在各人对话框里。
3. **多模型选型与交叉验证场景**：需要留档「每个模型说了什么、谁被驳回」，用于选型与对外交付留证。

**明确不卖**：多人实时协作、定时触发与上百个 SaaS 集成、SSO/RBAC 的企业客户——当前形态满足不了，硬卖会拖垮单人支持。

各层规模与付费意愿：**待验证**（M1 访谈 + 预订页测，不用二手报告）。

## 价值主张

一句话：**把「多个模型一起干一件真活」的过程变成一张能跑、能查、能交付的图。**

可感知的收益：看得见哪一步塌了（失败只重跑那个节点）；钱花在哪可解释（按模型分开的 token 观测，超预算弹选择卡而不是静默烧钱）；交接不靠人记（名册、手册、档位在运行时强制）；数据不出机器（key 与文件留在本地）；已有的 agent 不白学（会话接管让 Claude Code / Codex 拥有共享的、可视化的多模型状态）；交付物是图（可导出独立 HTML，别人 30 秒看懂流程）。

反向定位：不与 Claude Code 抢「写代码」，不与 n8n 抢「连应用」，不与 Dify 抢「发布成服务」。

## 产品形态与版本

- **Free（现有开源版）**：MIT 源码 + 便携版 + VS Code 扩展 + MCP/插件；核心闭环不阉割，保证「陌生人 10 分钟跑通示例」。
- **Pro（付费桌面授权）**：离线许可证文件、本地校验、不联网激活。付费边界放在**自动化与规模化**：自动续跑轮次、自省闭环预算循环与快照管理、运行历史归档与批量导出、多套团队名册切换、优先支持。
- **Team（预留，暂不做云）**：团队模板/手册包 + 只读导出与 `audit.jsonl` 审计 + 席位授权；等 Pro 有稳定付费用户后再开。
- **渠道形态**：VS Code Marketplace 扩展与 Claude Code 插件保持免费，作为获客入口；桌面版承载付费。

版本节奏：v0.1 预览（已完成）→ v0.5 付费试点（许可 + 升级页）→ v1.0 正式定价。

## 收入模型

1. **主收入：Pro 年度授权**（每用户每年）。不采用一次性买断——单人维护需要可预期的续费来覆盖支持时间。
2. **次收入：工作流/手册包**（一次性）。把「调研简报」「内容生产」「代码复审」等已验证可用的图连同手册打包，降低首次成功成本。
3. **补充：商业支持与定制咨询**（按天）。只接「用牵丝做自己的流程」，不接功能外包。
4. **不做**：代售 token 或按 token 抽成（无云、无合规主体，与自带 key 的本地优先承诺冲突）；广告与数据变现。

**怎么算账**（价格待验证，先给结构）：

```
年收入 ≈ Pro 年费 × 付费用户数 + 包单价 × 包销量 + 咨询日费 × 咨询天数
年成本 ≈ 支持工时 × 时薪 + 签名证书年费 + 商标/法务一次性
毛利 ≈ 年收入 − 年成本（边际成本≈0，真正的约束是支持工时）
```

决策线：支持工时/付费用户 > 可用工时的 20%，就停止扩量、先补文档与自助排查。

## 定价

- 原则：锚定「省下的模型浪费」与「一次重活的人工工时」，不锚竞品订阅价。
- 结构：Free 免费；Pro 年付，含 1 台设备离线许可与 12 个月更新；Team 按席位年付。
- 具体数字、早期用户折扣、学生/开源维护者折扣幅度均**待验证**——用预订页 + 访谈里的价格敏感度测试（愿意付/犹豫/拒绝三档），不靠猜。
- 不做永久免费 Pro，不做按调用量阶梯（调用量不在我们手里，无法计量）。退款 14 天无理由，换真实反馈。

## 获客渠道

按投入产出排序，每个渠道只做能复用内容的部分：

1. **GitHub + Release**：README 双语的「10 分钟跑通」是第一转化页；每版配真实运行 GIF 与产物截图。
2. **MCP / 插件生态**：Claude Code 插件市场与 VS Code Marketplace 是唯一「用户主动搜得到」的入口，安装压到一行。
3. **内容复用**：多模型分工复盘、同任务不同模型成本对照、自省闭环改代码的 diff 记录；一次实测多平台分发（博客/即刻/X/少数派/V2EX/HN/Reddit），不做日常运营。
4. **社区与私域**：Issue/Discussions 当支持台；活跃用户拉进小群做内测。
5. **合作**：AI 工具 newsletter 与测评作者，用免费 Pro 授权换真实长测评，不付软文费。

渠道转化率与获客成本：**待验证**；M2 前只记录绝对数（访问、下载、激活、付费），不设无法测量的 KPI。

## 成本结构

- **人力（最大成本）**：开发与支持同一人；支持时间最先撞墙。
- **模型 token**：自测、演示与问题复现；用户日常运行由自带 key 支付，不构成我们的成本。
- **代码签名证书**：Windows 签名尚未落地（当前 CI 出包、本机安全软件会拦截），年费**待验证**。
- **分发与托管**：GitHub Release 与静态导出页，成本接近零。
- **法务与商标**：命名查重清单已有，注册费用**待验证**。

边际成本结论：一份许可的增量成本接近零，成本曲线是「人力固定 + 支持随用户线性增长」——必须用文档与自助排查压支持工时。

## 风险与对策

| 风险 | 影响 | 对策与兜底 |
|---|---|---|
| 没人愿意付费（最可能） | 商业化失败 | M1 先卖后做：预订页无真实留资就不写 Pro 代码，退回开源 + 赞助 |
| 单人支持过载 | 质量与健康双崩 | 支持只走 Issue/邮件、限定响应窗口；文档与自助排查优先；拒绝定制 |
| 上游 API 与协议变动 | 核心功能间歇不可用 | 适配器 fixture 测试 + 探测接口 + 一键停用厂商；坏模型不拖垮整轮 |
| 付费墙易被绕过 / 开源被白嫖 | 收入漏损 | 接受漏损；离线许可只做「体面」级别，价值放在支持、模板与团队包 |
| 安全软件拦截与签名缺失 | 下载转化与信任受损 | CI 出包 + 校验和 + 文档说明；证书到位后再投渠道 |
| 大厂 agent 自带画布/多模型 | 差异被抹平 | 守住三点：本地优先、跨厂商、产物与验收可追溯；不与其通用能力正面竞争 |
| 关键人风险 | 项目停摆 | 文档齐全、发布流程脚本化、MIT 源码可被接管 |
| 法律与命名 | 上线受阻 | 沿用命名查重清单，商用前完成商标检索（费用待验证） |

## 验证指标

- **获客**：README 访问→下载、下载→首次启动、Star→下载；基线待验证，M2 后按周记录。
- **激活**：首次真实 live 运行完成率、示例 10 分钟跑通率、首次成功前放弃点。
- **价值**：7 日内第二次运行比例、每用户每周画布数、返修轮次、平均单任务验收分。
- **付费**：预订留资→付费转化、Pro 转化率、退款率、续费率、支持工时/付费用户。
- **成本护栏**：单次运行 token 上限触发次数、越过预算比例、模型失败自动降级成功率。
- **砍线（go/no-go）**：M1 无真实预订 → 停止 Pro 开发；M3 付费用户低于阶段内定目标且支持工时不可控 → 收缩为开源 + 赞助。

## 接下来 90 天能直接做的动作

1. **第 1–2 周**：把 README 的「10 分钟跑通」重写成带截图的分步教程，配一段真实运行 GIF；统计访问→下载基线。
2. **第 3–4 周**：做一个一页预订页（只有邮箱 + 「愿付价格档」三选一），在插件市场与 2 个内容渠道投放，凑够 10 份访谈。
3. **第 5–8 周**：仅当 M1 有真实留资，才做离线许可 + Pro 功能边界（自动续跑、自省预算循环、历史归档）。
4. **第 9–12 周**：首批付费与 3 篇可公开案例；同时把支持入口收拢到 Issue 模板，测支持工时。
