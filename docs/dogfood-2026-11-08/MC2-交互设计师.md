结论：切换器放顶部标题栏左侧/主工具栏，新建入口放切换器旁固定「+」；当前工作区用「文字名称 + 选中态 + 当前标签」标识；删除必须弹出带名称的不可恢复确认，只剩一个工作区时禁用删除；旧用户升级后首屏应看到「主画布」迁移提示，不要自动新建空白画布。

不确定项：参考资料未提供 Studio 实际 UI 稿，以下位置建议基于本地工具交互惯例，需产品最终确认。

## 可执行验收清单

1. 工作区切换器与新建入口
   - 切换器固定放在顶部标题栏左侧或主工具栏，不藏进设置页。
   - 触发控件显示当前工作区全名，超长截断并悬浮完整名称。
   - 新建按钮「+」永久可见，放在切换器右侧；点击后创建空白工作区并立即切换，不自动关闭下拉。
   - 下拉列表按现有 `createdAt` 升序展示；只展示接口返回的 `workspaces.json` 工作区，不额外展示未落盘的临时项。
   - 不绕过 `/api/workspaces` 接口直接改本地索引。

2. 当前工作区标识
   - 下拉打开后，当前项必须有明确选中态：背景色/边框 + 勾选图标 + 「当前」文字标签，三者至少同时出现，不能只用颜色区分。
   - 运行、写回、接续会话等落盘动作的目标工作区必须等于界面显示的当前工作区；当尚未实现的 SSE、MCP、VS Code 深链未传入工作区时，一律落在「当前工作区」，并在运行入口提示该目标名称。
   - 当前工作区名称发生切换后，画布、运行历史、任务列表立即刷新为新工作区数据，不允许出现旧内容残留或仅标题变化。

3. 删除确认
   - 删除入口放在切换器单项的「更多」或右键菜单，不直接暴露在主触发区，避免误触。
   - 删除确认框必须包含：工作区名称、明确提示「不可恢复，会同时删除该画布及运行历史」。
   - 确认按钮文案为「删除工作区」；取消按钮为默认焦点，按 Esc 必须能关闭。
   - 仅剩一个工作区时，删除按钮禁用并显示原因，而不是点击后报错。
   - 删除当前工作区后，自动切换到剩余列表中第一个工作区；如果删除成功后当前记录消失，界面不得停留在已删除工作区。

4. 旧用户升级后第一眼
   - 首次升级迁移完成时，顶部切换器显示「主画布」，并在切换器旁出现一次性提示条：「已把旧画布迁移到主画布，数据原样保留」。
   - 如果旧 `canvas.json` 不存在，切换器显示「空白画布」，提示条说明当前为空。
   - 升级后不得自动创建第二个空白工作区，也不得把旧画布改名。
   - 提示条关闭后不再重复出现，除非迁移失败；迁移失败时保留旧文件在 `~/.qiansi/` 原路径，不弹空白画布。
