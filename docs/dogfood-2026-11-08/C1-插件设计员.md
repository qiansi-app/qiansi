# qiansi-dsh bundle 设计说明

## 1. 文件结构

```
qiansi-dsh/
├── package.json
├── cordis.patch.yml
└── README.md
```

`qiansi-dsh` 自身不实现 MCP 协议，只作为 DSH 插件补丁包，通过 `dsh-mcp-client` 把牵丝的 MCP 工具注册进 DSH。

### package.json

```json
{
  "name": "qiansi-dsh",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "dependencies": {
    "@deepseek-ai/dsh-mcp-client": "0.2.2-rc.1"
  },
  "dsh": {
    "bundle": {
      "patch": "./cordis.patch.yml"
    }
  }
}
```

说明：`dependencies` 用于锁定桥版本，但 pnpm link 安装时不会安装被链接包的依赖，因此安装步骤中必须显式把桥装进 profile。

### cordis.patch.yml

```yaml
- insert:
    - id: qiansi-quota
      name: "@deepseek-ai/dsh-mcp-client"
      config:
        serverName: qiansi
        transport: stdio
        command: node
        args:
          - "C:/Users/<you>/.qiansi/mcp-server.cjs"
        env:
          QIANSI_HOME: "C:/Users/<you>/.qiansi"
        cwd: "C:/Users/<you>/.qiansi"
        toolCallTimeoutMs: 10000
        failOnStartupError: true
```

待确认项：输入材料没有给出牵丝 MCP server 的实际启动入口。上例用 `node C:/Users/<you>/.qiansi/mcp-server.cjs` 占位；如果实际提供 `qiansi mcp` 这类命令，应改为：

```yaml
command: qiansi
args: ["mcp"]
```

并确认 `qiansi` 在 DSH 进程的 PATH 中可用。

## 2. 安装步骤

前置条件：Windows 11、Node `>=24.9`、pnpm 12、DSH `0.2.2-rc.1` 已全局安装。

```powershell
node -v   # 预期 >= v24.9.x
dsh --version   # 预期 0.2.2-rc.1
pnpm --version  # 预期 12.x

# 1. 先装版本匹配的 MCP 桥到 profile
dsh plugin --profile qiansi add @deepseek-ai/dsh-mcp-client@0.2.2-rc.1

# 2. 再装 qiansi-dsh bundle
dsh plugin --profile qiansi add "link:C:\path\to\qiansi-dsh"

# 3. 验证补丁与解析
dsh --profile qiansi --dump-config
```

预期输出：`--dump-config` 中能看到 `id: qiansi-quota`，其 `name` 为 `@deepseek-ai/dsh-mcp-client`，且相关配置已展开；不应出现无法解析 `@deepseek-ai/dsh-mcp-client` 的报错。

## 3. 与 dsh-mcp-client 的衔接

- `qiansi-dsh` 通过 `cordis.patch.yml` 插入一个插件条目，该条目的 `name` 指向官方桥 `@deepseek-ai/dsh-mcp-client`。
- 桥读取 `config` 后，以 stdio 方式启动牵丝 MCP server。
- 桥会把牵丝 MCP server 暴露的 `get_quota` 工具注册为 DSH 工具，工具名形如：

```text
mcp__qiansi__get_quota
```

- DSH 会话中通过该工具名调用；额度数据来自牵丝 MCP server 读取 `~/.qiansi/keys.json` 后的返回值，密钥不得写入 `cordis.patch.yml`。
- `serverName` 应与 `id`/工具命名保持一致；同一 profile 内有多个 MCP server 时，避免 `serverName` 重复。

## 4. 至少两个可能的坑

### 坑 1：pnpm link 不安装 bridge 依赖，且版本错配会被拒

`dsh plugin add "link:..."` 底层走 pnpm，被链接包 `qiansi-dsh` 的 `dependencies` 不会自动安装。即使 `package.json` 里声明了 `@deepseek-ai/dsh-mcp-client`，profile 里仍可能解析不到桥。

更严重的是版本硬约束：`dsh 0.2.2-rc.1` 必须配 `dsh-mcp-client 0.2.2-rc.1`；`0.0.1-rc.1` 面向 `dsh 0.0.x`，安装会被拒。

处理方式：安装顺序固定为先显式安装桥，再安装 bundle：

```powershell
dsh plugin --profile qiansi add @deepseek-ai/dsh-mcp-client@0.2.2-rc.1
dsh plugin --profile qiansi add "link:C:\path\to\qiansi-dsh"
```

### 坑 2：Windows 路径与 stdio 启动参数

`cordis.patch.yml` 中如果写 `~/.qiansi/mcp-server.cjs` 或 `%USERPROFILE%\...`，在 Windows 下很可能不会被展开，导致 `spawn ENOENT`，DSH 启动失败。

处理方式：

- 使用绝对路径，并推荐正斜杠写法：`C:/Users/<you>/.qiansi/mcp-server.cjs`；
- `cwd` 必须真实存在；
- 如果牵丝 MCP server 依赖 `QIANSI_HOME`，在 `env` 中显式传入；
- `failOnStartupError` 建议保持 `true`，便于启动阶段发现启动失败；仅在调试时临时改为 `false`。

### 坑 3：工具名冲突或前端不知道工具名

桥会生成 `mcp__<serverName>__<tool>`。如果多个 patch 条目使用相同 `serverName: qiansi`，可能产生同名工具；同时 DSH 会话侧需要知道 `mcp__qiansi__get_quota` 这个工具名才会调用。

处理方式：`serverName` 在 profile 内保持唯一；在 README 中明确写出最终工具名。
