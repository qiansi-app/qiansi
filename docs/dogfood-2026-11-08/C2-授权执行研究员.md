## 1. 现状：dsh 的授权模型设计要点

**哲学层（docs/000-philosophy.md，二手一致转述，可信度高）**
- 第一性原理：“占用尽可能少的人类注意力，提供尽可能多的价值”，所有克制设计由此推导。
- 交互规约：接单确认一次→执行期静默→仅在交付（PR）/必须人拍板/彻底失败时开口；`Attention`（工单上待人工决定的问题）是正式领域概念。
- **主动性首先是授权问题**：只有“明确请求”或“团队成文规则”才动手；默认 observe 模式（只观察不出手）〔二手〕。

**授权层（docs/002-authorization.md 主线；对应 src/policy.ts、src/admission.ts、tests/policy.spec.ts——文件名为二手转述）**
- **授权与上下文硬解耦**：入站消息内容只能当上下文/输入，永远不能改变权限；权限只来自配置态（allowlist + 策略）与签发时的 Mandate。第三方安全审读验证了此命题成立〔一手代码可部分印证：runtime 中 `allowedSender, settingsPolicy` 与 Engine 的 `policy` 注入分离于消息流〕。
- **双入口 × 双强度**：Trigger 入口分 Eval（判定新工作请求）与 Subscription（既有工单的上下文扇出，不扩权）；强度分 explicit（明确请求，优先判定）与 inferred（规则推断），按序判定。
- **Mandate（不可变授权书）**：Eval 通过时签发，记录策略版本、范围、强度、命中规则、发送者身份、接收方式；扩权只能新建工单；**工单结束不自动撤销**，仅人的显式 stop 或策略不再覆盖时失效；**恢复（resume）/停止/策略变更时强制再验证**。
- **策略变更传播**：`settingsPolicy` 变化 → `engine.policyChanged(from, to, effects)`（runtime 一手代码），存量 Mandate 按新策略校验。
- **全局暂停阀（失效安全）**：`paused() = !configured() || settings.paused` 时冻结评估、派发、外发，但 Source 仍记录入站 trigger，恢复后继续（一手代码）。

## 2. 现状：dsh 的执行模型设计要点
- **Router/Worker 双层**：主会话（ROUTER_PRESET）负责连续性与分诊；每 Ticket 一个 worker session（`workerSessionId(ticket.id)`）+ 独立工作目录；工单状态含 open→ended→可恢复（存在 `ticket.resumed`、`trigger.followup` 事件，一手代码）。
- **角色化工具面 + 权限随深度递减**：`mainTools(agent)` vs `executorTools(host, ticket)` 按角色装配；worker 的 subagent **只继承工具限额（tool limits），不继承工具**（sessions 一手代码）。
- **执行环境注入**：`ticketEnvironment()` 生成 `Variable[]`（deployment/source/settings/trigger 派生）渲染进 worker 系统提示词（一手代码）。
- **幂等与审计**：Trigger 不可变，重复接收只创建一张 Ticket；Ticket 仅由 Eval 创建。
- **事件一致性 / 注意力预算**：Engine 领域事件 + `quiet` 计数器抑制主会话自己发起变更产生的通知；人的消息进入开启工单与主会话通知在同一事务；工单以 PR 结束时回原会话（一手代码）。
- **生命周期工程化**：Passes 驱动（receive/evaluateDue/request/pump/idle）；关停次序 assessor→agents.cancel(keepInbox)→executor→sessions→disposers→flush 持久化→关 DB→释放目录锁（一手代码）；组件级健康看板（runtime/models/worker/evals）。
- **已知短板（二手，可作牵丝反向提案素材）**：默认 worker 槽位少（约 3），卡死无告知且阻塞系统；完成瞬间的补充消息挽回率约 77%（20/26）；官方架构文提及的“模型驱动 Watchdog”在代码中不存在（第三方审读结论）。
- **效果数字（二手）**：约 300 条噪声消息中约 20 条真实请求的模拟流，p95 完成时间 15.7 分钟 vs 单会话基线 29.5 分钟（≈1.9×）。

## 3. 给提案员的候选素材（8 条原始提案点，未经“已借鉴”过滤）
1. **Mandate 式不可变授权对象**：签发即冻结策略版本/范围/强度/依据/身份；扩权=新单；resume 前强制再验证。
2. **授权-上下文解耦硬约束**：任何入站消息永不改权限，权限只来自配置态与 Mandate。
3. **explicit > inferred 两档判定器 + 按来源/范围的准入表 + 默认 observe 模式**。
4. **全局 paused 阀**：冻结评估/派发/外发但持续记录入站，恢复后重放（失效安全）。
5. **事件抑制（quiet 计数）**：主会话不被自己发起的变更刷屏——把“注意力预算”做成机制而非约定。
6. **权限随深度递减**：subagent 只继承工具限额，不继承工具面。
7. **每工单执行环境变量注入**：来源/部署/触发上下文渲染进系统提示词。
8. **补 dsh 短板**：worker 停滞/卡死检测 + 槽位耗尽告警 + 补充消息挽回归因（dsh 在这三处静默或漏接）。
