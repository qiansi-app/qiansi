# 提案员产出（魔鬼代言人模式）

> 说明：我未收到「牵丝已借鉴清单」原文（上游未转交），因此以下去重只能依据 C1/C2 文本推断，**不能保证无重复项**；凡依赖该清单的取舍都标为待核。另：C2 中 3 槽位、20/26、15.7 分钟、无 Watchdog 等均为**二手转述，未核源码**，本稿不作为事实引用。

## 0. 复述方案主张
上游主张：dsh-superagent-prototype 的「组合根 + 会话装饰 + 工具工厂按角色二分 + Mandate 不可变授权 + 授权-上下文解耦 + 全局暂停门 + quiet 事件抑制 + 优雅停机顺序」可移植到牵丝（本地多 AI 编排画布），以收敛权限面、降低注意力消耗、提高停机/恢复的工程可靠性。

## 1. 三条以上最强反对论证（每条附反例）

1. **对象形态错配**：dsh 是「单常驻 master 会话 + 每工单一 worker」的 ticket 机器人；牵丝是用户手绘的多 agent 画布，没有 ticket 生命周期。反例：用户想在一个节点同时调模型并外发通知，被「角色二分」强迫拆两个节点，画布可读性反而下降、用户绕过机制。

2. **本地单用户下授权防护大半空转**：dsh 防的是「入站消息诱导越权」（多人/外部触发）；牵丝本地单用户自己即最高权限，外部输入边界弱。反例：用户改了画布连线（即授权变更），旧 Mandate 未同步，执行按旧授权拒绝，用户找不到归因入口。

3. **quiet 抑制与画布可见性诉求正面冲突**：dsh 的 quiet 只抑制「主会话自己发起的变更」通知，防刷屏；但牵丝节点事件正是 UI 核心内容。反例：执行节点写文件失败但该事件被 quiet 吞掉，画布节点仍显示成功，用户到下游出错才返工。

4. **二手数字不可靠，据其立项风险高**：C2 的 3/20/26/15.7min 均为第三方解读转述。反例：按「worker 卡死无告知」立项做 30s 超时自动杀，实际慢模型被误杀，可完成的任务丢失。

## 2. 该主张在什么条件下才成立
- 牵丝有**后台常驻/无人值守运行**（定时、订阅、文件监听），而非纯手动「按运行键」；
- 牵丝有**可枚举的节点类型系统**（编排器 vs 执行器）且用户接受该约束；
- 牵丝存在**非用户本人控制的输入**（外部 API 回调、共享模板、导入工作流）且能触达敏感工具；
- 牵丝执行是**跨进程、可被中断的长任务**，而非浏览器内同步运行。

## 3. 提案清单（7 条；动机 / 改动 / 风险 / 性价比 / 最可能被推翻的地方）

**P1 工具面按节点角色二分（tool 工厂）**
- 动机：权限面随角色收敛，降低误触与注入影响面（C1-1、C2-6）。
- 改动：`tools/registry` 从全局静态注册表改为 `(node, role) => Tool[]` 工厂；节点类型加 `role`；装配点改到每次节点实例化。
- 风险：预设二分与自由画布冲突，破坏旧工作流的「单节点全能」。
- 性价比：中（有明确节点类型则高）。
- 最可能被推翻：牵丝不存在可枚举的节点角色，二分是凭空强加。

**P2 quiet 可重入回音抑制（只作用于面板通知通道）**
- 动机：节点执行引发的领域事件不回流触发同一节点/面板（C1-3、C2-5）。
- 改动：`EventBus.emit` 加整数 `quiet` 计数器 + `quietly(run)` 包裹器；只抑制「通知」通道，**不抑制审计/日志**。
- 风险：误吞用户关心的副作用事件。
- 性价比：高（改动小、可复用于任何自触发场景）。
- 最可能被推翻：牵丝事件模型若没有「自己触发自己」路径，quiet 是多余机制。

**P3 全局暂停门（冻结执行/外发，持续记录入站）**
- 动机：模型服务不可用或用户暂停时，画布保持可编辑、输入保留、恢复继续（C1-7、C2-4）。
- 改动：`Runtime/Executor` 加 `paused()` 谓词；入站 source 仍写 store；评估/派发/外发前检查。
- 风险：本地手动运行无持续入站流，「暂停中记录」退化为无谓队列；恢复重放旧输入可能与新配置不一致。
- 性价比：中（仅当有后台触发器）。
- 最可能被推翻：牵丝无持续入站，paused 退化为「禁用运行按钮」。

**P4 不可变授权书（Mandate）+ 授权-上下文硬解耦**
- 动机：agent 自主调用外部工具时，权限只来自配置态与已签发授权书，入站消息永不改权限（C2-1/2/3）。
- 改动：新增 `Mandate`（冻结策略版本/范围/强度/依据/身份）；`policy` 与消息流解耦；resume 前强制再验证。
- 风险：与画布「连线即授权」形成**双份真相来源**，易不一致；禁止「上游节点决定下游工具」的动态编排。
- 性价比：低-中。仅当引入代理模式或外部输入触达敏感工具才值得。
- 最可能被推翻：本地单用户权限边界太弱，属过度工程；且 `policy.ts`/`admission.ts` 内容为二手，须源码核验后才能立项。

**P5 每节点执行环境变量注入（来源/上游输出/触发参数渲染进系统提示词）**
- 动机：节点 prompt 可引用当前运行上下文而不硬编码（C2-7）。
- 改动：`execution-environment` 生成 `Variable[]`，模板渲染层支持注入。
- 风险：prompt 注入——外部触发内容（文件名、回调 body）直接进系统提示词可越界。
- 性价比：高（本地画布天然需要上游输出注入），但必须转义/模板化。
- 最可能被推翻：注入不经转义时，安全风险盖过收益。

**P6 优雅停机顺序 + 幂等 stop + disposers LIFO**
- 动机：停止时先取消所有 agent/子进程，再释放工具与资源（C1-5）。
- 改动：`stop()` 幂等共享 Promise；`disposers` 数组 reverse 释放；停机顺序注明因果。
- 风险：本地子进程强杀可能写坏文件，需临时文件+原子替换；无跨进程执行时是空转。
- 性价比：高（纯工程可靠性）。
- 最可能被推翻：牵丝若无跨进程/可中断执行，此模式无对应用途。

**P7 执行停滞检测 + 槽位告警 + 失败归因（补 dsh 短板）**
- 动机：dsh 已知 worker 卡死无告知、槽位耗尽静默、补充消息挽回率低（C2-8）。
- 改动：超时/心跳 + 健康看板 + 失败分类。
- 风险：**阈值依据（3/20/26/15.7min）为二手，不可直接作参数**；超时自动杀会误杀慢模型。
- 性价比：中。仅长耗时无人值守才值。
- 最可能被推翻：本地画布用户肉眼可见卡死，检测是过度工程；阈值依据不可靠。

## 4. 上游结论逐一「最可能被推翻的地方」

C1：
1. 工具工厂按角色二分 → 角色二分是「最小注意力」的推断（C1 自标仅个人判断），未必是作者意图；牵丝无对等角色体系时不成立。
2. 状态目录锁+锁内启闭 → 单用户本地单进程下无并发写威胁，锁+abort 是过度防御。
3. quiet 整数化 → 整数可能只是防御性编码，不证明「嵌套重入」是真实场景。
4. 组合根 emit 分层 → 分层是偏好而非必需；照搬会让组合根更膨胀。
5. disposers LIFO+停机顺序 → 依赖「工具释放早于 worker 结束」这一具体坑；牵丝无对应时序则不适用。
6. master id 持久化+ensure → 牵丝画布可能无「常驻会话实体」，重启恢复对象不同。
7. paused 门 → 无持续入站的本地画布不需要「记录入站」，重放语义可能错。

C2：
1. Mandate → `policy.ts`/`admission.ts` 语义为二手，未核源码；本地单用户价值低。
2. 授权-上下文解耦 → 若用户期望「上游决定下游能力」的动态授权，硬解耦直接禁止。
3. 两档判定器+准入表+observe → 判定器细节全为二手（docs/002 转述）；默认 observe 可能让交互式画布「点了没反应」。
4. paused 阀 → 同 C1-7。
5. quiet → 同 C1-3。
6. 权限随深度递减 → 牵丝 subagent/嵌套执行模型若不存在，无落点。
7. 环境变量注入 → 外部输入进系统提示词的注入风险未评估。
8. 补短板 → 数字全二手；「卡死/槽位」是 dsh 单编排器瓶颈，牵丝未必有同等瓶颈。

## 5. 风险清单与触发条件
- **R1 双份真相来源**：触发=P4 落地且用户可随时改连线；应对=仅对「代理模式」节点签发 Mandate，手动连线不签发。
- **R2 prompt 注入**：触发=P5 把外部输入直接注入系统提示词；应对=模板转义+外部内容不进系统指令控制段+告警。
- **R3 quiet 吞失败事件**：触发=P2 抑制范围扩到审计通道；应对=只抑制「面板通知」，审计/日志不抑制。
- **R4 暂停重放配置漂移**：触发=P3 恢复时重放旧入站；应对=重放前校验入站签名/配置版本，不匹配则置为待人工处理。
- **R5 阈值依据不可靠**：触发=P7 用二手数字定超时；应对=先源码核验，或只「先告警、不自动杀」。
- **R6 停机强杀写坏状态**：触发=P6 强 kill 子进程中途写文件；应对=临时文件+原子替换，先 cancel 后 flush。
