## 三、面向用户的使用说明

**什么时候需要人点「续跑」**：运行失败或被中断、且未带 autoResume 意图时。三处入口：
1. 聊天 / API：经 run.start 发起续跑（resumeOf）
2. MCP：调用 resume_project
3. 界面：「需要人工」面板中失败与中断条目上的「续跑」按钮

**续跑会做什么**：只重新执行没有产出的任务；已完成任务的产出自动作为上游上下文注入；续跑任务带「恢复说明」。模型与 Key 优先沿用上一轮模型档案，档案缺失时按画布节点当前模型——中途换过的模型和 Key，续跑也能用上。

**什么情况会自动续跑**：
- 运行带 autoResume 意图，失败或中断后自动排下一次续跑，最多 2 轮，到上限即停并留审计
- 服务重启后：被上次进程中断且带该意图的运行会自动接着跑
- 人为停止的运行不参与自动续跑

**配套能力**：每轮结束由旗舰模型复盘，verdict / score / suggestions / action 在运行结果中可读；有任务失败或平均验收分 <0.6 时自动发起一轮多模型讨论，产物「讨论 · 为什么没达标」落在画布。服务重启会把残留运行记为「运行已中断」，可从「需要人工」面板续跑。

**待明确（以实际产品为准）**：resumeOf 在聊天/API 中的具体参数、autoResume 的配置入口与参数名，资料未说明；人工停止的运行能否手动 resumeOf 亦未明确（仅明确其不参与自动续跑）。
