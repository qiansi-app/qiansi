# 牵丝 DSH 插件 · 可执行验证清单

> 环境假设：Windows 11 + PowerShell 7；`dsh` 已全局安装；`$env:DSH_HOME` 已设置。
> 所有「预期输出」均为**形态示例**（版本号/路径按你的机器替换），判断依据是**匹配规则**，不是逐字相等。
> 标注 `❓不确定` 的条目需先用 `dsh --help` / `dsh plugin --help` 确认子命令名再执行。

---

## G0 前置闸门：工具链版本

| # | 命令 | 预期 | 失败判断 / 处置 |
|---|---|---|---|
| 0.1 | `node -v` | `v24.9.0` 或更高 | 低于 24.9 → dsh 拒绝启动，先升 Node |
| 0.2 | `dsh --version` | 输出含 `0.2.2-rc.1` | 不匹配 → `npm i -g dsh@0.2.2-rc.1`；**版本不符后续必定连锁失败** |
| 0.3 | `pnpm -v` | `12.x` | 缺失 → `dsh plugin add` 底层 pnpm 报错 |
| 0.4 | `echo $env:DSH_HOME` | 非空绝对路径，如 `C:\Users\me\.dsh` | 空 → 后续 `profiles\<名>` 路径全部错位 |

```powershell
$nodeV = (node -v).TrimStart('v')
if ([version]$nodeV -lt [version]'24.9.0') { "FAIL node 版本过低: $nodeV" }
if ((dsh --version) -notmatch '0\.2\.2-rc\.1') { "FAIL dsh 版本不是 0.2.2-rc.1" }
```

## G1 包契约自检（安装前，纯本地，不需 dsh）

**命令**
```powershell
$PkgDir = 'C:\work\qiansi\packages\qiansi-dsh'   # 改成你的实际目录
Push-Location $PkgDir
node -e "const p=require('./package.json');console.log(p.name+'|'+p.version+'|'+JSON.stringify(p.dsh&&p.dsh.bundle))"
Pop-Location
Test-Path (Join-Path $PkgDir 'cordis.patch.yml')
```

**预期**
```
qiansi-dsh|0.1.0|{"patch":"./cordis.patch.yml"}
True
```

**失败判断**
- 输出 `undefined` 或 `null` 的 bundle 段 → `package.json` 缺 `"dsh": { "bundle": { "patch": ... } }`，`dsh plugin add` 会当成普通包安装、不注册补丁。
- `patch` 指向的文件不存在 → 路径写成相对 `package.json` 的 `./cordis.patch.yml`，注意大小写（Windows 不敏感、CI/Linux 敏感）。

**补丁形状检查（`- insert:` + 每项 `id/name/config`）**
```powershell
$patch = Get-Content (Join-Path $PkgDir 'cordis.patch.yml') -Raw
$patch -match '(?m)^\s*-\s*insert:'          # 期望 True
([regex]::Matches($patch,'(?m)^\s*-\s*id:')).Count   # 期望 = 你声明的条目数（≥1）
$patch -match '(?m)^\s*name:'                 # 期望 True
```
**失败判断**：`insert:` 为 `False` → YAML 缩进错了（`insert` 必须是顶层数组项的 key）；条目缺 `name` → 该条目被静默跳过，只在 dump-config 里表现为"少了一条"，不会报错。

## G2 dump-config（**装插件之前**先验补丁能被解析）

**命令**
```powershell
Push-Location $PkgDir
dsh --profile qiansi-dev --patch .\cordis.patch.yml --dump-config *> dump-before.txt
"exit=$LASTEXITCODE"
Select-String -Path dump-before.txt -Pattern 'qiansi-dsh'
Pop-Location
```

**预期**
```
exit=0
dump-before.txt:  - id: qiansi-dsh
dump-before.txt:    name: qiansi-dsh
dump-before.txt:    config:
```

**失败判断**
| 现象 | 含义 | 处置 |
|---|---|---|
| `exit != 0` | YAML 语法错 / `!!js` 表达式求值抛错 | 读 `dump-before.txt` 末尾堆栈；先删掉 `!!js` 段落复跑，二分定位 |
| `exit=0` 但搜不到 `qiansi-dsh` | 补丁没被读取（路径错）或条目名写错 | 用绝对路径 `--patch (Join-Path $PkgDir 'cordis.patch.yml')` 重试 |
| 条目在但没有 `config:` | 配置被写成空对象，插件会拿默认值跑 | 回 G1 检查 patch |

## G3 插件安装（link）

> ⚠️ 关键坑：`link:` 安装**不会**装被链接包自己的依赖。

**命令**
```powershell
$Profile    = 'qiansi-dev'
$ProfileDir = Join-Path $env:DSH_HOME "profiles\$Profile"

dsh plugin --profile $Profile add "link:$PkgDir" 2>&1 | Tee-Object install.log
"exit=$LASTEXITCODE"
```

**预期**
```
... Progress: resolved ... linked ...
+ qiansi-dsh 0.1.0 <- link:C:\work\qiansi\packages\qiansi-dsh
exit=0
```

**失败判断**
- `ERR_PNPM_LINKED_PKG_DIR_NOT_FOUND` → `$PkgDir` 路径含空格未加引号，或目录不存在。
- `exit != 0` 且日志含 `engines` / `node` → G0 版本闸门没通过。
- 成功但日志里**只有 qiansi-dsh 一个包** → 这是正常的（link 不装依赖），**必须继续 G4**。

**安装后的 profile 落盘校验**
```powershell
Get-Content (Join-Path $ProfileDir 'package.json') -Raw | Select-String 'qiansi-dsh'
Test-Path (Join-Path $ProfileDir 'node_modules\qiansi-dsh')
```
**预期**：`package.json` 的 `dependencies` 中出现 `"qiansi-dsh": "link:..."`；第二条 `True`。
**失败判断**：`dependencies` 无此条目 → 插件装到了别的 profile（用 `dsh plugin --profile <名> list` 核对）；`Test-Path` 为 `False` → Windows 上符号/junction 创建失败，改用管理员终端重跑，或直接 `copy` 而不是 `link`。

## G4 模块解析（两跳都要通，否则运行期才炸）

**命令**
```powershell
Push-Location $ProfileDir

node -e "try{console.log('OK', require.resolve('qiansi-dsh'))}catch(e){console.error('MISS qiansi-dsh');process.exit(1)}"
"r1=$LASTEXITCODE"

node -e "try{console.log('OK', require.resolve('@deepseek-ai/dsh-mcp-client'))}catch(e){console.error('MISS dsh-mcp-client');process.exit(1)}"
"r2=$LASTEXITCODE"

Pop-Location
```

**预期**
```
OK C:\Users\me\.dsh\profiles\qiansi-dev\node_modules\qiansi-dsh\dist\index.js
r1=0
OK C:\Users\me\.dsh\profiles\qiansi-dev\node_modules\@deepseek-ai\dsh-mcp-client\dist\index.js
r2=0
```

**失败判断**
| 输出 | 结论 | 修复命令 |
|---|---|---|
| `MISS qiansi-dsh` / `r1=1` | link 未生效 | 回 G3 |
| `MISS dsh-mcp-client` / `r2=1` | **最常见的坑**：link 不装依赖 | `dsh plugin --profile $Profile add @deepseek-ai/dsh-mcp-client@0.2.2-rc.1` |

**版本匹配硬校验（必须 rc 对齐）**
```powershell
$bp = Join-Path $ProfileDir 'node_modules\@deepseek-ai\dsh-mcp-client\package.json'
(Get-Content $bp -Raw | ConvertFrom-Json).version
```
**预期**：`0.2.2-rc.1`
**失败判断**：得到 `0.0.1-rc.1` 或其他 → 该版本面向 dsh 0.0.x，安装时会被拒或运行期接口不匹配；清掉后按上表命令重装。

**被链接包自身依赖（第三跳，可选但推荐）**
```powershell
node -e "try{console.log(require.resolve('@deepseek-ai/dsh-mcp-client',{paths:['$PkgDir']}))}catch(e){console.error('MISS from pkg dir');process.exit(1)}"
```
**失败判断**：若这里 MISS，说明 qiansi-dsh 的 `dependencies` 里没声明 MCP 桥 → link 场景下必然解析失败，应在 `package.json` 里声明为 dependency（而非 devDependency）。

## G5 MCP 工具注册

### 5.1 静态：桥插件条目进了配置

```powershell
$dump = dsh --profile $Profile --dump-config 2>&1 | Out-String
"exit=$LASTEXITCODE"
$dump | Select-String 'dsh-mcp-client'
$dump | Select-String 'serverName'
$dump | Select-String 'transport'
```

**预期**（形态示例）
```
exit=0
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: qiansi
    transport: stdio
    command: node
    args: [ 'C:\work\qiansi\packages\qiansi-dsh\dist\mcp-server.js' ]
    failOnStartupError: true
```

**失败判断**
| 现象 | 含义 | 处置 |
|---|---|---|
| 搜不到 `dsh-mcp-client` | 桥没装进 profile，或 patch 里没写这条 insert | 先过 G4-r2，再查 patch |
| 有 `serverName` 但值为空/`undefined` | `!!js` 表达式取环境变量失败 | 换成字面量先跑通，再恢复表达式 |
| `command` 是 `npx` / `node` 无 `.cmd` | **Windows 专属坑**：`spawn` 不解析 `.cmd` 需 `shell:true` | 改成 `node` + 脚本绝对路径，或写 `npx.cmd` |

**stdio 启动命令可达性**
```powershell
# 若 command 是 node + 脚本路径：
Test-Path 'C:\work\qiansi\packages\qiansi-dsh\dist\mcp-server.js'   # 期望 True
# 若 command 是可执行名：
Get-Command qiansi-mcp -ErrorAction SilentlyContinue                 # 期望有输出
```
**失败判断**：`False` / 空 → 先 `pnpm build` 产出 `dist`；运行期会报 `spawn ENOENT`。

### 5.2 运行时：工具真的注册成 `mcp__qiansi__<tool>`

> dump-config **只列插件条目，不列工具名**；`mcp__<serverName>__<tool>` 是启动期由桥动态生成的，只能在会话里验。

❓不确定：`dsh` 是否有直接列工具的只读子命令（如 `dsh mcp list`）。先用 `dsh --help` 确认；没有就走下面的会话验证。

**命令（会话验证）**
1. `dsh --profile $Profile` 启动会话；
2. 发一句：`请调用 mcp__qiansi__get_quota，不要做其他事`；
3. 观察工具调用与返回值。

**预期**
- 工具面板/调用记录里出现 **`mcp__qiansi__get_quota`**（前缀 = `serverName`，**不是**包名 `qiansi-dsh`）；
- 返回 JSON 含各模型家族的 key 槽位与日/月额度余量，形如 `{ "keys": [ { "family": "deepseek", "daily": {...}, "monthly": {...} } ] }`。

**失败判断**
| 现象 | 结论 | 处置 |
|---|---|---|
| agent 说 "no such tool" / 工具列表为空 | 桥没加载或 stdio 子进程秒退 | 手工单跑：`node <mcp-server.js>` 看是否输出 MCP 握手；再查桥日志 |
| 工具名是 `mcp__qiansi-dsh__get_quota` | `serverName` 被写成了包名 | 改 patch 里 `serverName: qiansi`（短名，避免双下划线歧义） |
| 工具在但调用超时 | `toolCallTimeoutMs` 太小 / 牵丝侧 HTTP 未起 | 调大超时；先 `curl http://127.0.0.1:<port>/api/keys` 确认服务在 |
| 工具在但返回 401/空额度 | 牵丝 `~/.qiansi/keys.json` 无 key 或已用尽 | 属业务态，非接入故障；界面「更多 → 密钥与额度」核对 |

### 5.3 负向测试（验 `failOnStartupError`，别跳过）

```powershell
# 临时把 command 指向不存在的路径，或在 patch 里改成 command: node / args: ['nope.js']
dsh --profile $Profile --dump-config *> dump-bad.txt
"exit=$LASTEXITCODE"
Get-Content dump-bad.txt -Tail 20
```
**预期**：`failOnStartupError: true` 时**启动失败并明确报桥启动错误**（exit≠0 或日志含 spawn/ENOENT）。
**失败判断**：静默启动、工具静默缺失 → `failOnStartupError` 未生效，这会让"插件装好了但工具没了"变成不可观测故障，必须修 patch。测试后**改回原配置**。

## 一键脚本（把 G0–G5 串起来，输出 PASS/FAIL）

```powershell
# verify-qiansi-dsh.ps1
$ErrorActionPreference = 'Continue'
$PkgDir     = 'C:\work\qiansi\packages\qiansi-dsh'
$Profile    = 'qiansi-dev'
$ProfileDir = Join-Path $env:DSH_HOME "profiles\$Profile"
$script:fail = 0
function Check($name, $cond, $hint) {
  if ($cond) { "PASS  $name" } else { "FAIL  $name  -> $hint"; $script:fail++ }
}

# G0
Check 'node>=24.9' (([version]((node -v).TrimStart('v'))) -ge [version]'24.9.0') '升级 Node'
Check 'dsh=0.2.2-rc.1' ((dsh --version) -match '0\.2\.2-rc\.1') 'npm i -g dsh@0.2.2-rc.1'
Check 'DSH_HOME 已设置' ([bool]$env:DSH_HOME) '设置 $env:DSH_HOME'

# G1
$meta = (node -e "const p=require('$($PkgDir -replace '\\','/')/package.json');console.log(JSON.stringify({n:p.name,b:p.dsh&&p.dsh.bundle}))") | ConvertFrom-Json
Check '包名=qiansi-dsh' ($meta.n -eq 'qiansi-dsh') 'package.json name 错'
Check '声明 dsh.bundle.patch' ($meta.b.patch -eq './cordis.patch.yml') '补 dsh.bundle.patch'
Check 'patch 文件存在' (Test-Path (Join-Path $PkgDir 'cordis.patch.yml')) '路径/文件名错'
$patch = Get-Content (Join-Path $PkgDir 'cordis.patch.yml') -Raw
Check 'patch 含 - insert:' ($patch -match '(?m)^\s*-\s*insert:') 'YAML 缩进错'
Check 'patch 条目有 name' ($patch -match '(?m)^\s*name:') '条目缺 name 会被静默跳过'

# G2 装前 dump
Push-Location $PkgDir
$before = dsh --profile $Profile --patch .\cordis.patch.yml --dump-config 2>&1 | Out-String
$c2 = $LASTEXITCODE
Pop-Location
Check '装前 dump-config exit=0' ($c2 -eq 0) '看 stderr：YAML / !!js 求值错'
Check '装前 dump 含 qiansi-dsh' ($before -match 'qiansi-dsh') '补丁未被读取'

# G3 安装
dsh plugin --profile $Profile add "link:$PkgDir" *> install.log
Check 'plugin add exit=0' ($LASTEXITCODE -eq 0) '看 install.log'
Check 'profile package.json 含 qiansi-dsh' ((Get-Content (Join-Path $ProfileDir 'package.json') -Raw) -match 'qiansi-dsh') '装错 profile'
Check 'node_modules/qiansi-dsh 存在' (Test-Path (Join-Path $ProfileDir 'node_modules\qiansi-dsh')) 'junction 创建失败'

# G4 解析
Push-Location $ProfileDir
node -e "try{require.resolve('qiansi-dsh')}catch(e){process.exit(1)}"; Check 'require.resolve(qiansi-dsh)' ($LASTEXITCODE -eq 0) '回 G3'
node -e "try{require.resolve('@deepseek-ai/dsh-mcp-client')}catch(e){process.exit(1)}"; Check 'require.resolve(dsh-mcp-client)' ($LASTEXITCODE -eq 0) 'dsh plugin add @deepseek-ai/dsh-mcp-client@0.2.2-rc.1'
Pop-Location
$bp = Join-Path $ProfileDir 'node_modules\@deepseek-ai\dsh-mcp-client\package.json'
Check 'MCP 桥版本=0.2.2-rc.1' ($bp -and (Get-Content $bp -Raw | ConvertFrom-Json).version -eq '0.2.2-rc.1') '版本硬约束不符'

# G5 静态注册
$after = dsh --profile $Profile --dump-config 2>&1 | Out-String
Check '运行前 dump 含 MCP 桥条目' ($after -match 'dsh-mcp-client') 'patch 缺桥 insert 条目'
Check 'serverName=qiansi' ($after -match 'serverName:\s*qiansi') 'serverName 写成包名/为空'
Check 'transport 已声明' ($after -match 'transport:\s*(stdio|streamable-http)') '缺 transport'

"`n==== 失败项: $script:fail ===="
if ($script:fail -gt 0) { "未通过，修完再跑运行时验证（G5.2 / G5.3）" } else { "静态全部通过 → 继续 G5.2 会话内验证 mcp__qiansi__get_quota" }
```

## 需要你确认的不确定项（未验证，不要当结论）

1. `dsh plugin remove` 的确切子命令名与参数形态——未核实，用 `dsh plugin --help` 确认。
2. `dsh` 是否存在直接列出已注册 MCP 工具的只读子命令；若无，工具注册只能靠 G5.2 会话验证。
3. `--dump-config` 的实际输出格式（YAML / JSON）——上述 `Select-String` 匹配同时兼容 `key: value` 与 `"key": "value"` 两种，但字段层级需按你机器上的首份 dump 校准。
4. `serverName` 最终取值（本文按 `qiansi` 写），需与 patch 内实际值一致，否则 `mcp__<serverName>__get_quota` 前缀对不上。
