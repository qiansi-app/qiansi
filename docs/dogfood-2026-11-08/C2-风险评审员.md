# 风险评审：qiansi-dsh 设计（针对 C1 设计说明）

## A. 版本匹配

**A1 依赖声明与实际解析脱节**
package.json 里的 `@deepseek-ai/dsh-mcp-client@0.2.2-rc.1` 只是声明；`link:` 安装不会装依赖，DSH 只从 profile 解析。用户跳过第 1 步直接 add bundle 时，失败要等到 `--dump-config` 才暴露，设计无任何前置检测。
建议：安装步骤增加第 0 步检查：
```powershell
dsh --profile qiansi --dump-config | Select-String "dsh-mcp-client"
# 无输出则先执行：
dsh plugin --profile qiansi add @deepseek-ai/dsh-mcp-client@0.2.2-rc.1
```
（不确定：`dsh --version` 确切输出格式，正则需实测后固定。）

**A2 升级漂移无护栏**
dsh 升到 0.2.2 正式版或 0.3.x 时桥必须同步换版，是硬约束，但没有任何机制强制。
建议：README 写升级矩阵（dsh 0.2.2-rc.1 ↔ client 0.2.2-rc.1；dsh 0.0.x ↔ client 0.0.1-rc.1）；升级 dsh 后必须重装匹配版本桥并 `--dump-config` 复核。保持精确 pin，禁用 `^`（如日后用 pnpm 追加依赖，加 `-E`）。

**A3 双份桥共存**
手动装桥 + 其他工具又给 bundle 装依赖时，profile 可能出现两个版本。
建议：装完检查 `--dump-config` 中 `@deepseek-ai/dsh-mcp-client` 只出现一次且版本一致；否则移除旧条目（remove 子命令确切语法未验证，标注）。

## B. 路径

**B1 绝对路径硬编码 `<you>` 占位**
`C:/Users/<you>/...` 按机器写死，换机器/换用户即失效；忘替换占位符直接 spawn ENOENT。
建议：改为生成式 patch——bundle 附 `scripts/render-patch.mjs`，用 `os.homedir()` 渲染真实路径写入 cordis.patch.yml，安装步骤插一步 `node scripts/render-patch.mjs`。若实测确认 patch 支持 `!!js` 启动期求值且可 require os/path（契约提到 `!!js`，但能否 require 内置模块未验证），可改用：
```yaml
args: [!!js "require('path').join(require('os').homedir(),'.qiansi','mcp-server.cjs')"]
```
实测确认前不要依赖。

**B2 `~` / `%USERPROFILE%` 不展开，且不止 args**
C1 已指出 args 的问题，但 `cwd` 与 `env` 值同样不展开。
建议：三者一律用渲染后的绝对路径（正斜杠）；render 脚本同时 `fs.existsSync` 校验 cwd 与 server 文件，缺失即报错退出。

**B3 QIANSI_HOME 自定义时错位**
用户若把 .qiansi 放非默认位置，硬编码路径全错。
建议：render 脚本读 `process.env.QIANSI_HOME ?? homedir()+'/.qiansi'`，并确保渲染时与 DSH 运行时是同一用户、同一环境来源。

## C. Windows

**C1 裸命令 `qiansi` 在 Win11 大概率起不来**
npm 全局 bin 是 `.cmd` shim；新版 Node 对无 shell 的 `.cmd` spawn 直接 EINVAL。设计中备选方案 `command: qiansi` 不可用。
建议：主方案固定 `command: node` + 绝对 `.cjs` 路径（设计默认已是），README 明确「不要用裸 `qiansi`」；确需命令入口用 `command: cmd`、`args: ["/c","qiansi","mcp"]`。

**C2 `failOnStartupError: true` 的爆炸半径**
牵丝未装或文件缺失时整个 profile 起不来，殃及该 profile 其他工作。
建议：保留 true（fail-fast 有价值），另附调试模板 `cordis.patch.debug.yml`（false + 日志）；排障顺序写明：先在终端手动 `node <绝对路径>/mcp-server.cjs` 观察是否常驻不退出（server 是否有 probe 参数未验证，标注），再进 DSH。

**C3 `toolCallTimeoutMs: 10000` 未必够**
get_quota 理论上只读本地文件，10s 足够；但 keys.json 被独占锁定或 server 冷启动时可能超时（锁定行为取决于 server 实现，未验证）。
建议：server 侧每次调用即读即返回、不做长缓存；超时放宽到 30000，成本几乎为零。

## D. 断线重连

**D1 stdio 子进程崩溃无恢复方案**
设计完全未提 server 崩溃后的行为；桥是否自动重启子进程未验证。表现为会话中途 `mcp__qiansi__get_quota` 消失，需重启 DSH。
建议（不依赖桥内部行为的三层防线）：
1. server 永不因单次工具错误退出：每个请求 try/catch，错误以 MCP error response 返回；keys.json 解析失败时备份坏文件并回退空配置。
2. 日志写文件而非 stdout/stderr：stdout 被 stdio 协议占用，stderr 可能被桥捕获，均不可靠——写 `%QIANSI_HOME%/logs/mcp-server.log`。
3. README 写明恢复动作：工具消失 → 重启 `dsh --profile qiansi`，并把重启后调用一次 get_quota 列入验证清单。
（不确定：桥若有 restart 类 config 字段应优先使用，以官方文档为准。）

**D2 额度数据陈旧**
若 server 缓存 keys.json，DSH 长会话里看到旧余量，误判「无余额可切」。
建议：get_quota 每次实时读盘（本地文件开销可忽略），返回中带 `readAt` 时间戳便于确认新鲜度。

## E. 安全

**E1 get_quota 返回值可能带出密钥**
C1 只约束了「密钥不写入 patch」，没覆盖返回值泄漏：keys.json 含 secret，原样序列化会把密钥带进 DSH 会话上下文（可能被模型输出或日志记录）。
建议：server 返回前做字段白名单（slot/id/家族/日耗/月耗/余量/启停），secret 只保留尾 4 位；补一条单测断言：序列化输出不含完整 secret。

**E2 env 透传最小化**
patch 的 env 会随 `--dump-config` / profile 共享而暴露。
建议：env 只保留 `QIANSI_HOME` 一项；render 脚本断言生成的 yml 不含 `secret|token|apikey=` 形态的值。

**E3 `!!js` 等于可执行配置**
patch 支持 `!!js` 启动期求值，patch 文件即任意代码；若 profile 被同步到仓库/网盘，拉取即执行。
建议：qiansi-dsh 的 patch 默认不含 `!!js`（用 B1 render 脚本替代）；若采用，README 注明「patch 属可执行配置，勿安装来自不可信来源的 patch」。

**E4 `link:` 指向的本地目录可被篡改且即时生效**
任何有该目录写权限的人改动文件，下次 DSH 启动即生效。
建议：bundle 放用户私有目录（不放共享盘）；团队分发改用打包/固定版本安装而非 link（dsh 是否支持 link 场景的哈希校验未验证，标注）。

## F. 补充：验证缺口

**F1 `--dump-config` 只证明配置解析，不证明桥拉起了 server、工具已注册。**
建议：安装步骤增加第 4 步运行期验证：
```powershell
dsh --profile qiansi
# 会话内调用 mcp__qiansi__get_quota
```
预期：返回各家族 Key 额度 JSON，无 secret 字段。失败判定：ENOENT → B1/B2 路径问题；版本被拒 → A2；工具名不存在 → serverName 拼写错误或 server 未注册工具。
